# Product documentation artwork

Both language homepages lead with user tasks and link to the [topic guide](../../docs/topics.md). Preserve the shared header artwork and use existing captures to show actual tasks. Put format inventories in compatibility references; do not use the wall as the primary explanation of the product.

The file-format wall is generated by `python3 scripts/generate-format-wall.py`. It embeds existing Material Extensions file icons and purpose-made category glyphs so GitHub can render it without external images or scripts. Their MIT notice is embedded in each SVG; the source license is retained in [file-icons/LICENSE](../file-icons/LICENSE).

`formats.svg` and `formats-dark.svg` contain the same representative formats. `†` marks limited previews. The wall is an overview, not a promise of complete rendering for every format. Keep it aligned with [format support](../../docs/file-format-support.md).

README download links use the stable GitHub `/releases/latest` page. Do not pin a release tag or a versioned installer filename; users choose the matching platform asset on that page. Only macOS Apple Silicon and Intel installers are part of current releases.

[repository-banner.svg](../branding/repository-banner.svg) is the shared header artwork for both READMEs. Keep it unchanged unless explicitly requested. Its file cards are a branding illustration.

`workspace.png` and `sqlite.png` are user-provided product captures. The first shows a Markdown report with an embedded GitHub Star chart; the second shows filtered records in a SQLite snapshot from the same workspace. Both language READMEs use these full, unmodified captures. Do not infer product usage metrics from the chart: it is document content, not Glim adoption data. Captions and alternative text should describe the visible task.
