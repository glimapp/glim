# Architecture

**English** · [简体中文](architecture.zh-CN.md) · [Documentation](README.md)

Glim is a focused file viewer for macOS on Apple Silicon and Intel. Readers share a tabbed workspace. Ordinary UTF-8 text supports basic editing and autosave; images and binary/document previews are read-only.

## Floating reader actions

`reader/controls` supplies bottom-center, content-overlay capsules for CSV/Geo tables, paged text/hex, book controls, XMind and image pagination. Titles, catalogs and sheet navigation remain separate. Scrollable content includes end clearance, and embedded book/source pagers offset their capsules to avoid overlap. GPUI capsules use theme-based translucency, borders and shadows; they do not implement backdrop blur or optical refraction.

`native/FloatingReaderToolbar.swift` supplies the matching AppKit surface for image/SVG, PDF, media, font, XLSX and Office actions. SQLite uses a persistent sidebar and navigation footer. It uses public `NSGlassEffectView` on macOS 26+ when built with a supporting SDK; SDK detection defines `GLIM_NATIVE_GLASS` in both native builds. Older SDKs/systems retain `NSVisualEffectView` without increasing the macOS 11 minimum. Wide native action sets scroll within the capsule; media controls leave AVKit's transport clear. SVG content stays in the isolated streamed image document; native buttons invoke only the wrapper's image commands. Common native toolbars omit file-byte and query-timeout retry actions; complete byte paging remains available in fallback readers. The unused file-byte polling bridge is removed. Visible control widths are measured from current labels and selectors, then placed in a frame-managed scroll document; stack fitting sizes and flexible spacer frames are not measurement inputs. The capsule shrinks to visible content; overflow exposes left/right scroll buttons and keeps full-sized controls in the viewport. Hidden-state and label changes are remeasured before reveal and on drawing. GPUI capsules are bounded by the actual parent width. Reader action capsules are invisible until the pointer dwells in a broad transparent bottom zone. Reveal and dismissal are delayed; pressed-button drags freeze visibility, and releasing a drag does not reveal controls. The hidden native zone passes clicks through to the document. They size to their visible controls; buttons retain bordered surfaces distinct from secondary status labels, and row/column paging groups appear only when needed.

## Modules and dependency direction

```text
crates/
  glim-core/src/       document and update values; no I/O or GPUI
  glim-services/src/   filesystem, watchers, format parsing, backups and preferences; no UI
  glim-app/src/
    app/              startup, actions, menus, locale, diagram engine and updater coordination
    views/
      workspace_window.rs  window-level ownership and workspace-tab switching
      workspace/      readers, tabs, loading, navigation, editing and update-session restoration
      reader/         source, markup, data trees/tables, images, native previews, XMind
      explorer.rs     lazy directory tree, sticky ancestors and filename/path tooltips
      minimap.rs      document overview
native/               embedded macOS previews, settings helper and Sparkle bridge
assets/               branding, file icons, syntax queries, offline engines and bundle metadata
scripts/              packaging, signing, feed generation and focused native checks
```

Dependencies are one-way: `glim-app → glim-services → glim-core`; app may also use core directly. GPUI Kit is pinned and Cargo.lock retained. Blocking file work runs on the background executor. Render methods compose cached state, not filesystem scans or commands. Views retain their entities, subscriptions and cancellable task handles.

## Shared reader policy

`assets/reader-limits.json` is the single source for application reading thresholds, organized by reader with typed values, units, effects and descriptions. `scripts/generate-reader-limits.py` validates it and generates Rust constants, Swift ReaderLimits and embedded JSON into each Cargo OUT_DIR. `glim-services::limits` exposes the Rust values; app presentation uses that module directly, native preview targets compile the generated Swift, and the private diagram WebView receives the same value map. Builds track the policy and generator, and CI path filters include both. No reader performs runtime policy-file I/O. See [the generated inventory](reader-limits.md); update it with the generator’s `--docs` option. Readers use streaming, paging or complete source fallbacks instead of total-file caps. Working budgets bound active processing, not access to complete files.

## Workspace and editing

Workspace creation and release control `app/telemetry` resource sampling; the registry filters expired entities and removed windows. Sampling stops without a live workspace and resumes on opening one. The updater retains 300 ms polling while windows or update work are present, and polls every five seconds while windowless and idle. The local GPUI window patch rejects input queued after window removal.

Each window owns a `WorkspaceWindow` with an uncapped, ordered list of retained `Workspace` entities. Sidebar workspace tabs are flat, appear below Home, and support inline rename from their context menus. Switching workspaces retains readers, drafts, Explorer state and background saves; hidden workspaces suspend native presentation and foreground usage tracking. Window close and application quit protect drafts in every workspace. Update-session snapshots preserve workspace identities, names and window grouping. Each workspace has independent folder roots and document tabs. Adding folders appends root entries in order, including repeated paths and parent/child paths; another window can add the same folders. Explorer tracks expansion, selection and element identity per root occurrence while sharing directory data by path within the window. Top-level root context menus can remove an individual entry without deleting files or closing open tabs. Explorer emits a stable root identity; Workspace updates its roots, search scope, recent history and watchers. Removing the last root leaves open files watched independently and removes the empty workspace from recent history.

Workspace owns tabs, Explorer entities, navigation history and asynchronous loading. File tabs use paths as identity. Reopening activates an existing tab/window. Finder file opens use a retained queue for every format, including unsupported files; errors stay in tabs.

Workspace presentation uses the existing grayscale theme tokens: Start navigation lives in the compact sidebar (20% of window width by default; double-clicking its resize divider restores that ratio, dragging below 120 px collapses it, and its maximum width is 50%); a collapsed sidebar retains a narrow icon rail with Home and Show File List controls, while the content surface begins directly with document tabs, including when only one file is open. `workspace/toolbar` owns the action definitions, reader-capability selection, ordering, icons, labels, selection/availability states, shared button rendering and action dispatch for the outer toolbar. It presents navigation first, document viewing/layout controls next, and update availability last; readers expose supported capabilities rather than toolbar code maintaining a separate file-extension allowlist. Sidebar/back/forward navigation follows the Glim brand and a divider in the outer title bar; reader-mode and word-wrap controls occupy its right side as uniform icon buttons. The title bar also owns sidebar visibility and a permanently visible search input centered on the window, with results anchored below it. Saving stays available through autosave, the menu and ⌘S; there is no save button or saved-status footer. These controls reuse the existing reader entities and asynchronous save operations. `app/menus` owns the three macOS menus (Glim, File and View). About, Settings and an intentionally duplicated update-check entry live under Glim; refresh remains available through its shortcut, and File → Close Window closes every workspace in the current window; ⌘, opens Settings in the current workspace. `workspace/settings` owns the theme and language selectors plus default file-type management, update checks and keyboard-shortcut help. Language selection is cached in the app and applied without reading preferences during rendering. The theme selector provides System, Light and Dark choices. Services retain the appearance preference, and the app serializes its writes; each workspace retains an appearance observer to update the theme when macOS changes while System is selected. Sidebar density and reading size are fixed, and ordinary text autosaves without a settings toggle. Start and Settings hide native reader views without disposing document tabs.

The Start page places Open New Workspace, Open File and New File in one row at a 2:1:1 width ratio, with single-line icon/label/shortcut content, a stronger brand-green workspace entry and neutral file entries. Its logo sits above the actions without a slogan. Recent workspaces include the current workspace and use compact 44 px single-column rows with aligned names and paths, a tinted current-workspace state, and muted inline icons for explicit new-window opening and history removal. Clicking a recent workspace selects or appends it in the current window; opening a new workspace prompts for a folder. Sidebar file/folder creation and folder append controls operate on the selected workspace. Workspace names in the sidebar and recent list do not show hover tooltips. Each sidebar workspace has a close icon that removes it only from this window, retaining recent history and protecting unsaved changes through the shared save/discard flow; closing the last workspace returns to an empty Home workspace. The window owns the shared navigation scroll handle, reveals the active workspace after selecting or opening it, and paints subtle top/bottom edge fades only when content remains beyond that edge. `app/workspace_sessions` caches ordinary workspace sessions by stable workspace ID, independently of update checkpoints. `services/preferences` atomically persists them in `workspace-sessions.json`; tab opens/closes/reordering, active-file changes, reader-mode changes and workspace closure update the cache through serialized background writes, drained at application shutdown. Recent-workspace opening in either window mode and startup restoration reuse ordered file/playlist descriptors, the active file and preview/source mode through `workspace/session`. Missing files remain visible as unavailable tabs. Unsaved drafts stay in the existing recovery/save-confirmation flow; generic scroll/cursor positions are not part of this session record. Removing a history entry does not close its live workspace or delete files. Services atomically persist optional display names and folder lists in `recent-workspaces.json`; the app caches this list and serializes background writes. Folder names supply the default display name, and renaming a workspace does not rename folders on disk.

The document toolbar also provides per-window file fullscreen: it hides the sidebar and tabs, expands the active reader, and retains a compact title bar with viewing controls and an exit button. Escape exits this mode. Sidebar sizing/visibility and reader entities are preserved; macOS App fullscreen remains independent.

Closing a workspace window affects only that window and keeps its unsaved-change guard. The app uses explicit quit behavior: closing the last window leaves Glim running; reopening from the Dock creates a workspace window. File → Close Window (⌘⇧W) closes the current window; ⌘W closes its current tab or its empty window. Only Quit Glim / ⌘Q requests application-wide exit, with the existing update-install exit gate retained.

Folder roots are persisted atomically in `workspace.json`. Ordinary startup restores recent roots, not a complete general-purpose tab session; untitled notes have separate local recovery checkpoints. Update restarts additionally consume a one-time tab session; see [updates](auto-update-design.md).

Refreshes preserve reader state where supported and never replace a dirty draft. Obsolete task results are ignored after navigation; already-running blocking work may finish, but its result is not installed. Watchers coalesce filesystem events across workspace roots and open files, including `target`, `node_modules` and `dist`. Explorer refreshes run independently of reader loading, content refreshes and saves; reader refresh requests remain pending until those operations finish. Directory scans finish before replaying changes received during a scan, avoiding cancellation starvation during event bursts. Horizontal content scrolling takes precedence over navigation gestures.

`SourceReader` retains `EditorState` for typing, selection, undo/redo, search and folding. Tree-sitter handles supported grammars; lightweight visible-line coloring covers other configurations/templates without LSP. Autosave queues each file after approximately 800 ms idle and keeps explicit ⌘S/Ctrl+S. Same-directory temporary files provide atomic replacement; disk-baseline conflicts preserve the draft. Close/quit checks unsaved content and pending saves.

File icons use Material Icon Theme 5.39.0 with Glim-specific format associations. `scripts/generate-file-icons.mjs` imports the pinned upstream inventory and generates `views/file_icons_data.rs`, `app/file_icon_assets.rs` and the SVG/48 px PNG assets together. `assets/file-icons/manifest.json` records provenance and the complete associations. The shared resolver uses case-insensitive directory-qualified filename suffixes, exact basenames, contextual Docker/environment/CI rules, then longest compound suffixes and a neutral fallback; light-theme variants follow the live theme. Explorer, tabs and search use the same resolver. Assets are embedded and binary-searched without filesystem reads or runtime JSON parsing. Icon recognition does not expand reader/editing capabilities.

`reader/markup` uses TextView for Markdown and an embedded WebKit view for HTML. Preview and source share editing state; format-specific preferences survive refresh/reopen. Unchanged source reuses rendered state. HTML previews render CSS and JavaScript from the editor snapshot; the source editor remains available. JSON/CSV entities parse editor snapshots in retained background tasks; their read-only projections do not replace editable source. Markdown preview preparation in `services/markdown_preview` tolerates blank lines between explicit pipe-table headers, delimiters and matching rows. It uses top-level Markdown AST block ranges to preserve code, HTML, math and frontmatter, and changes only preview text. The editor and saved source retain their original bytes; preview images, diagrams and heading ranges use the same normalized text. CSV and TSV share a persisted reading-mode preference (`csv-view`); new ordinary and paged readers use the last selected table/source mode, while refreshing an existing reader preserves that reader’s mode. A rejected preview switch does not update the preference. When opening a CSV/TSV in table mode, the workspace replaces the old document with a centered preview-loading state during file reads; the table reader uses the same state during parsing and page loads. Existing reader entities remain retained, and errors follow the normal reader error path.

Markdown task checkboxes are opt-in editable controls in ordinary Markdown previews. The pinned `vendor/gpui-base` TextView patch adds `on_task_toggle` while retaining its native list layout, virtual blocks, selection and read-only default. `workspace/reader_actions` routes clicks to the live source editor, then through the existing save queue, autosave and external-change conflict protection. `reader/markup` validates the preview generation and source snapshot, maps preview-only table omissions back to original source bytes, and changes only the task marker using an undoable editor edit. Preview scroll position and source selection are preserved. Locked, HTML and generated-format previews remain read-only; hand-written summary counts are not recomputed.


Every file opening retains its tab, including Explorer single clicks, double clicks, Enter, explicit Open and Finder requests. Opening an existing file reuses its reader; opening another file does not replace an earlier tab. Tabs have no count limit or temporary/kept distinction. File/folder activation uses live workspace handles and existing folder roots; opening a folder already present activates its workspace. Finder file requests leave Start/Settings for the document page, including when reusing a reader. Directory listing, media discovery and watch setup retain cancellation guards so closing or replacing their owner stops work between entries/paths.

Markdown source edits preserve the preview block/offset, applying it only after the corresponding asynchronous parse completes and clamping to the new block count. CSV source mode offers a dismissible per-workspace table hint routed through the shared reader action and persisted mode preference. HTML navigation polling runs only while its native preview is shown. PDF close clears selection and document references; fit-width changes scale only when the resulting device-pixel width differs, avoiding subpixel layout churn. Resource telemetry remains observational and does not attribute main-process memory to one reader.

Native updater snapshots include fixed error stage/kind, numeric error code and check availability. The update panel offers classified recovery guidance, retry when Sparkle accepts a new check, and a manual-release link. New checks and successful startup clear stale error state; arbitrary native error text stays local.

## Diagrams and format readers

`services/markdown_preview` parses/deduplicates diagram and formula blocks, invokes private `--render-markdown`, and rasterizes bounded SVG output. `app/diagram_engine` uses WebKit on its process main thread with bundled offline engines. Visible diagram and formula nodes enqueue resource requests into bounded background batches. Completed resources update a shared cache and invalidate inline layout without reparsing the document. Leaving preview cancels work and releases the reader cache; cancellation terminates the renderer. macOS bundles a background `GlimRenderer.app` (`LSUIElement=true`); unbundled builds use the executable's renderer mode. Rendering does not depend on Node, Java or a remote service.

Mermaid, Graphviz, PlantUML, flowchart.js, WaveDrom and MathJax are embedded with their licenses. Local Salt/Chen adapters cover a subset of syntax. External diagram resources, navigation and downloads are blocked; failures preserve source. Engine source and bundled resources live in [scripts/markdown](../scripts/markdown) and [assets/markdown](../assets/markdown).

`services/formats`, `text_formats` and `vector_formats` supply bounded container listings/text extraction, basic reading projections and static mesh/bitmap-font images. Dedicated ebook reading belongs to `services/books` and `reader/books`; these generic projections do not execute document code. `services/media` decodes bounded images. Large standalone PNGs share the ImageIO thumbnail preparation in `services/inline_images`, reading from a temporary snapshot of the captured bytes so the preview and fingerprint stay consistent; workspace loading displays immediate status feedback. Its `GifPlayback` owns a sequential GIF decoder and bounded compositing/restore buffers; `reader/media::GifReader` retains a cancellable playback task, supplies individual BGRA frames directly to GPUI, and releases replaced textures. GIFs composite at original resolution, but displayed frames are bounded to a 2,048px longest edge. Playback uses absolute deadlines and two lookahead batches (each at most three frames / 16 MiB); expired intermediate frames are not uploaded. Frame disposal and finite loops are preserved without GPUI’s whole-animation image cache. Hidden tabs pause decoding; closing cancels playback and releases the current texture. Per-reader budgets and boundaries are maintained in [formats and limits](file-format-support.md).

`services/xmind` reads modern JSON or legacy XML from bounded ZIP content without extraction. Container reads and decompression use the loading cancellation token. UTF-8 BOMs and root-only legacy XML DOCTYPE declarations are accepted; external/internal DTD definitions remain unsupported. Parsing or graph-budget failure falls back through workspace/loading to complete content.json/content.xml pages and emits reader_fallback with a fixed phase. Damaged containers, missing source entries and cancellation remain errors. Its UI-independent sheet/topic model includes notes, labels, floating roots and relationship endpoints. `reader/xmind` owns sheet selection, folding, zoom, scrolling and topic details; layouts are cached and GPUI paints visible nodes/links with theme tokens. The reader is read-only and uses ordinary loading, refresh and update-session paths.

## Embedded macOS previews

`native/Preview.swift` and `EmbeddedPreview.swift` implement PDFKit, AVKit, Quick Look, CoreText and worksheet index views embedded in workspace tabs. They do not launch separate preview apps or Dock icons. App build.rs compiles the Swift static library. `reader/native_bridge` owns the narrow main-thread-only unsafe FFI boundary and attaches NSViews to the GPUI AppKit window; the native-preview, context-menu and updater bridges are the app’s scoped unsafe exceptions, while remaining app code denies unsafe and core/services forbid it.

`services/matroska` validates bounded EBML structure and remuxes H.264/AAC-LC samples to a temporary MP4 for AVKit. AVC parameter sets come from track configuration or Annex-B frames; MP4 composition offsets preserve reordered frames. `services/preview` retains temporary media and maps original paths to playback paths, preserving file identity and labels. No FFmpeg installation or subprocess is required; see [format limits](file-format-support.md).

`services/preview::prepare` validates files and prepares playlists, database snapshots and disk-backed worksheet indexes off the UI thread. Each `reader/native` entity retains its controller and prepared data. Native framework loading is scheduled on the main queue rather than inside GPUI render/layout. Switching hides views and pauses media while retaining local page/playback position; closing releases native resources before temporary data. Toolkit overlays temporarily hide native views. Accessibility nodes and responder-chain actions are integrated into the main window.

SVG image previews reuse `HTMLPreview` and its streamed local-resource handler after service-side sanitization. A static image document owns one scroll viewport and fit/actual-size/zoom controls; SVG scripts and links do not execute. Raster images retain ImageIO. Image previews omit the file-byte footer. Raster scroll clips center documents on both axes when smaller than the visible area, and fit mode recomputes on viewport resize. Explorer and document-tab context menus use the scoped `views/native_menu_bridge` AppKit bridge, which tracks selections asynchronously and cancels on owner drop. These menus layer above native previews without hiding, pausing or replacing readers; only an explicitly selected action changes file/workspace state. Browser-image preparation preserves data-URI images (including nested SVG without rasterizing), XHTML `foreignObject` labels and complete stylesheets, while the SVG image sandbox prevents document scripts and external loads. Percent/missing root dimensions resolve from the viewBox (or the other absolute dimension) before zoom sizing.

PDF and Office/iWork remain read-only. `services/spreadsheet` streams XLSX relationships, shared strings and worksheet XML into a temporary SQLite index. A disk-backed worksheet-position cache generates bounded presentation workbooks for the selected row/column page. Native Quick Look uses its normal full-sized style, constrained to all four reading-area edges, to render those pages with cell styles, widths, heights, merges and cached values; formulas are not recalculated. The complete address/value/formula index stays internal; the separate Cell data UI is removed. Presentation copies omit charts and drawings; shared-string rich text retains text but not per-run formatting. The private app helper performs page generation in a cancellable subprocess. Legacy XLS and unsupported workbook structures use Quick Look. Fonts are inspected, not installed. Audio artwork/metadata load asynchronously with cancellation; decorative playback animation respects reduced motion and is not a spectrum analyzer.

`services/sqlite` streams database/WAL/journal data into a private snapshot and checks source stability; SHM is rebuilt in the copy. `services/sqlite/browser` runs read-only rusqlite queries on background workers; `reader/sqlite` presents them with GPUI. No Swift/NSView bridge is used for SQLite. Sources are never checkpointed or written. Missing-main sidecars show bounded information.

`native/PreviewMain.swift` is only the separate default-file-type settings helper. It changes Launch Services handlers after explicit selection/confirmation, records old handlers, and does not overwrite a user's later changes during restoration.

## Directory browsing

Explorer expands newly added roots one level, leaving descendant folders collapsed. It restores per-root expansion state from `explorer.json` during ordinary workspace restore and update-session restore; writes are atomic, serialized and awaited on quit. Tab activation reveals the active file by loading its ancestors in retained background tasks, selecting it and scrolling it into view; the latest requested file wins. Explorer loads direct children on expansion; both directory listings and filename searches include dotfiles and files excluded by Git or ignore rules, hide `.git` and do not recursively follow symlinks. Cached background media checks control folder playback menus; rendering does not scan folders. Blank-space and row context menus are separate.


## Platform, preferences and update boundaries

The maintained workspace uses GPUI on macOS Apple Silicon and Intel with ⌘ shortcuts. Swift provides native previews and default file-type settings; diagrams use system WebKit. Windows application/service branches have been removed; the build script explicitly rejects non-macOS targets.

macOS bundle identity remains `io.github.jony4.glimpse` for compatibility. Preferences use `~/Library/Application Support/Glim`, with legacy Glimpse fallback where implemented. Locale dictionaries are embedded; document text and technical diagnostics are not translated. Each documentation topic has English and Simplified Chinese counterparts.

`glim-core/update` defines snapshots, modes, activity guards and session values. `services/updates` verifies/copies backups and writes/consumes bounded session checkpoints. `app/updates` owns one global `UpdateState`, task handles, editing locks and exit-generation checks; `views/updates` renders a reusable centered window. Menu/About/titlebar entries share that state. Finder opens arriving during exit preparation withdraw approval and preserve the file request.

The macOS `macos-updater` feature connects `app/updater_bridge` to Sparkle 2.10.0 in `native/Updater.swift`. Its custom user driver delegates install approval to Rust. The bridge adds the missing cancellable termination method to the fixed GPUI delegate without replacing it; incompatible future delegate contracts disable updating. Sparkle handles signed downloads, extraction, permissions and replacement. Unconfigured builds offer manual downloads. Only the two Mac architectures receive signed update feeds.

See [update behavior and trust](auto-update-design.md), [release setup](releasing.md#automatic-updates) and [remaining work](TODO.md).


## Markdown network images and executable inspection

`app/image_http` registers a GET-only GPUI image transport. Network and decoding work runs on the background executor through `services/markup_images`, with shared timeout, redirect and minimum-transfer-rate budgets, streaming responses into temporary files without a total download cap. The service returns bounded image data, uses system fonts for SVG, blocks external SVG resources and returns a visible placeholder on failure. GPUI owns static asset caching and refresh; render methods perform no network or file I/O. The maintained transport uses system curl on macOS and converts GitHub repository `blob`/`raw` image URLs to `raw.githubusercontent.com`, with a GitHub Contents API raw-media fallback for conventional ref/file URLs when the raw host fails. Both attempts share the configured network timing policy. The unauthenticated API fallback is subject to GitHub rate limits; link destinations and source text are unchanged.

`reader/pictures` retains cached theme candidates and cancellable parsing tasks. Markdown HTML nodes and HTML documents are parsed in the background. `reader/markup` selects picture sources for the current theme without rewriting editor contents, anchors or user files. `reader/pictures` also prepares one persistent sequential player per resolved `.gif` image URL (local or HTTP), shared by duplicate references. Markdown image resolution supplies its current frame directly through a custom GPUI image source, including while initially loading, so embedded GIFs bypass the whole-animation cache. Parsing ignores code examples; network/file work is background-only, removed references release players, and hidden/source-only previews cancel playback and release decoding buffers while retaining compressed GIF data; unfinished animations restart when shown again, and completed finite GIFs keep their final pixels. Unknown media conditions use the img fallback; conflicting candidates for the same fallback URL are left unchanged.

`services/inline_images` prepares static document-image previews with a maximum 2,048px edge, using the built-in macOS `sips`/ImageIO thumbnail path under a shared preparation lock. Rust only decodes the bounded thumbnail, avoiding full-size raster buffers in the viewer; remote inline rasters use the same path after the streamed download. Local SVG uses the bounded raster service. `reader/pictures` retains one `InlineImageReader` per resolved static URL and activates only the current theme candidate; hidden/source-only documents cancel preparation and release their pixels. Inline static previews may lose detail when enlarged, while source files and standalone image-reader limits are unchanged. Image-atlas eviction is deferred until the current rendering window has been returned to the app, so hiding a document also evicts that window's textures.

`services/executables` recognizes Mach-O, universal Mach-O, ELF and PE headers and uses object for read-only architecture, segment, section and available dependency metadata. A seekable metadata cache bounds active memory independently of file length; complete names are scanned incrementally. Metadata working-budget exhaustion falls back to complete hexadecimal pages. Inspected programs are never loaded or executed. `workspace/loading` routes this content into the existing read-only byte reader before attempting text decoding, without separate preview windows.

## Ebook reading

`services/books` reads bounded EPUB package metadata/spines and EPUB3 nav or EPUB2 NCX, FB2/FB2 ZIP structure and embedded illustrations, and naturally ordered CBZ pages. Chapters are loaded and sanitized on the background executor; XML entity declarations, archive path escapes, scripts and automatic external resource loads are rejected. Image previews have per-chapter encoded/decoded budgets. Resources stay in memory and are not extracted into document directories.

`reader/books` retains chapter parse entities, resource images, focus/scroll handles and cancellable loading tasks across renders. Its book surface supplies serif/sans-serif typography, font size, line height, page width, paper tint, TOC, chapter/page navigation, bookmarks and position restoration. Preference writes are serialized through a retained task and a coalesced state buffer; update exit checks wait for book writes as well as ordinary file work. `books/preferences` stores book-specific reading state under the application preferences directory keyed by content fingerprint; it never edits the original book.

### Shared UI localization

`glim-services::locale` owns message lookup for the Rust UI and the translation payload passed to native previews. English message strings are canonical IDs. `assets/locales/en.json` supplies the fallback catalog; every locale has matching keys and a `__language_name` entry containing its language-name message ID. Catalogs are discovered and embedded by the services build script, and settings enumerates them automatically. Add a complete `<BCP-47-code>.json` file to introduce a language without editing language switches. Explicit language preferences are checked against the discovered catalogs; system matching tries the full locale, then its language, then English.

`scripts/check-locales.py` checks duplicate keys, catalog parity, nonempty translations, interpolation tokens, literal Rust/Swift message references and Chinese text in the English catalog. The services build runs it automatically. Translate application labels and generated preview chrome through the shared catalog; keep user content, paths, application names, language/format names and technical diagnostics intact. Native controls use `L`, Rust uses `locale::tr`; interpolated messages keep their named tokens and HTML output escapes translations. GPUI component-owned controls retain the component library's own locale support; adding a catalog does not supply translations for that library's internal controls.

### File creation and recoverable removal

`workspace/file_operations` creates Untitled tabs (⌘N) without asking for a destination. Folder menus retain the preferred first-save directory. `app/recovery` retains a single `services/drafts` background worker; pending checkpoints coalesce per note, and atomic private snapshots preserve UTF-8 text and the preferred directory under Application Support/Glim/Drafts. Owner-only directories and OS session locks keep other running Glim processes' drafts separate. Startup claims abandoned sessions and restores their notes without deleting unreadable recovery records. Explicit discard or a completed save removes the checkpoint; normal shutdown drains queued writes/removals. A crash can still lose edits that had not reached the background checkpoint. Recovery failures are reported so users can save explicitly.

Drafts stay out of disk refresh, watching, navigation history, Trash actions and update-session file descriptors. Existing files retain autosave. Draft Save uses the native save panel, including macOS replacement confirmation; known binary/container extensions prompt for another name instead of pretending to export that format. `services/files` captures a cancellable, streamed digest of existing destinations, rejects targets already open in Glim, and checks identity/content again before atomic replacement. New targets use exclusive publication. First save preserves the live editor, selection and undo history; changes made during the write remain dirty and enter the save queue, retaining recovery until the latest contents are saved.

`workspace/editing` resolves Save / Don't Save / Cancel before tab, folder or window closure. App quit gathers per-window approvals without deleting drafts; cancellation preserves previously approved notes, and subsequent edits invalidate approvals. Only final all-window approval commits discard cleanup. Switching back to a source tab focuses its editor. Regression cases cover checkpoint restart/discard, active-session isolation, destination replacement/conflicts and text-format boundaries.

`workspace/file_operations` confirms moves to Trash and coordinates the existing cross-window filesystem mutation lock, keeping autosave and other file operations from racing deletion. After success it closes affected live tabs and removes matching workspace roots in every window. Explorer entries and ordinary file tabs expose the action; removing a folder from the workspace remains a separate non-filesystem operation. `glim-services::workspace::trash_entry` runs on the background executor under the save mutex and invokes the bundled native helper's `--trash` mode. Foundation `FileManager.trashItem` handles recoverable, volume-aware moves without following a selected symlink or falling back to permanent deletion.

ImageIO previews defer their initial fit until the embedded view is attached and its scroll viewport has a valid size. Decoding and the first layout share a centered loading state; a zero-sized viewport never commits an almost-zero image scale.

### Browser HTML preview

`reader/markup` retains a `NativeReader` for HTML while keeping the ordinary source editor, saving and reading-mode preferences. HTML source mode does not initialize WebKit until preview is requested; switching back to preview uses the current editor snapshot. `native/HTMLPreview.swift` owns a persistent WKWebView, CSS/JavaScript execution, fragment navigation and a loading/error state. A nonpersistent website data store isolates preview storage. Local links return through the native bridge to Glim's existing file/URL navigation, so the displayed document and source tab do not silently diverge. Popup/dialog overlays and inactive tabs hide the native surface.

A private `glim-html` URL scheme serves the snapshot without project-directory temporary files. Its cancellable serial background reader streams local assets using the shared IO buffer budget; symlink-resolved paths must remain within the enclosing Git project, or the document directory when no Git root is found. The root is discovered and cached on the resource worker, so relative `../` styles/scripts in sibling project directories work without blocking native layout. Network resources use WebKit. The scheme differs from a normal HTTP origin; pages requiring a backend, secure-origin APIs, browser extensions or unrestricted filesystem access may need a development server or a full browser. Large HTML uses the same resource worker to stream the original document instead of building a full editor snapshot. Its editable source pages remain available; save a modified page before returning to preview. WebKit still owns its DOM and script allocations. This browser path is separate from Markdown's static inline-HTML handling and the isolated offline diagram renderer.

## Diagnostics and file failure isolation

`glim-services::diagnostics` owns a bounded background log writer under `~/Library/Logs/Glim/`. Logs use local calendar dates, rotate before 8 MiB per file and retain at most 14 log files (including current-day segments); startup and rotation prune older segments. The bounded queue accepts ordinary messages without blocking rendering; panic records request a synchronous flush with a two-second acknowledgement timeout. Logs include startup/version, file open/read/reader initialization, tab activation, saves and toolkit Info/Warn/Error messages. Panic records include the owning file path, phase, thread, source location and forced backtrace; file contents are not logged. Ordinary queue overflow may drop diagnostic events.

`reader::boundary` attributes the complete lazy file layout/prepaint/paint subtree to a file. The panic hook quarantines that path for the current process. A local patch of pinned `gpui-pre` 0.3.8 (`vendor/gpui-pre/GLIM-PATCH.md`) catches acknowledged file draw panics before the macOS callback, restores entity leases/update depth and the layout engine, discards partial frame state and drawing stacks, and forces a clean frame. The failed file becomes an error page with its full path, retry and log-folder controls; other tabs and unsaved editor entities stay alive. File read and reader-construction unwinds become file failures. Retry is explicit; quarantine resets at app restart. Abort-mode panics, OOM, stack overflow, native exceptions and unrelated app panics are outside this unwind boundary.

### Scalable readers

`services/geo` streams GPX/KML coordinate pages; `services/xml` decodes XML references consistently for Geo and XLSX. `services/paged` owns editable UTF-8 pages and cancellable atomic range replacement; refresh preserves the current page and unchanged editor state. `services/streamed` recreates canceled codecs and retains a bounded rolling cache. Large cell/schema dialogs use byte windows or disk-backed source pages. Diagram blocks render in active-page batches with complete source retained. Book chapters retain navigation and use full text/hex member pages when structured rendering exceeds working budgets. Native image decoding is serialized and raster output stays within the decoded-memory budget; logical dimensions and full source bytes remain available. This is scaled preview, not region-based full-resolution decoding. SDK allocations, ZIP central-directory indexing and SQLite expression evaluation remain platform/library constraints.

Markdown preview uses TextView’s viewport-bound virtual block list rather than a natural-height whole-document widget. Table normalization only builds an AST when blank-separated pipe rows may need repair. Image and diagram discovery skip AST construction when their required syntax markers are absent. Initial preview text is enqueued after plugin configuration; diagram and formula resources update independently of the parser revision to avoid duplicate full parses. Background parsing shows a centered loading state until content is available; state completion refreshes the reader. The minimap seeks and tracks the same virtual list, and anchors use its built-in range reveal. Offscreen blocks are laid out on demand; a single large block still depends on the toolkit’s block layout implementation.

The shared scheduling direction, format-specific representations, current implementation and remaining work are documented in [Rendering pipeline](rendering-pipeline.md). Diagram batches pre-analyze engine dependencies and import only required offline ESM modules; font files use memory mapping and successful raster results share a bounded in-process cache. The asset build embeds the complete module manifest in the app; no runtime project-folder scan is needed.

Markdown workspace refresh also checks referenced local still-image metadata on background workers, even when the Markdown source itself is unchanged. Changed images are decoded again; the old frame remains visible until the replacement is ready. Remote images do not participate in this filesystem refresh.

Office and workbook external-open actions resolve the current Launch Services handler at click time. When Glim owns the association, the action offers compatible applications excluding every bundle with Glim’s identifier, plus an application picker. Opening uses an explicit application URL and does not modify file associations; picker selections are checked again to prevent reopening Glim.

`services/word_preview` prepares read-only DOC/DOCX/RTF reading projections using the system textutil converter in a serialized, cancellable subprocess. Generated HTML stays on disk and is decorated with fixed IO buffers and the shared active-record budget. Font sizes become relative to readable root typography; paragraph/list emphasis is retained and the document uses the full viewport width. `native/WordPreview.swift` defaults to the full-width reading view; native Quick Look remains available for original pagination, table grids and merged cells. Its toolbar offers an explicit Reading mode / Original layout switch; reading mode uses a JavaScript-disabled, nonpersistent WebKit surface with zoom out/in, percentage and reset. Conversion/load failure keeps native layout available. Dark reading mode overrides imported text/background colors for legible text and table borders. The native controller closes before its prepared projection directory is removed. Reading view changes pagination and can differ for complex tables, drawings, embedded objects, headers/footers and typography; the original remains available. Conversion failure falls back to native layout without a total-file-size rejection. System importer/WebKit internal allocations remain framework constraints. Pages and native spreadsheet previews (including Numbers) use normal Quick Look; only slide previews retain the compact undecorated style.

Shared reader actions retain their relative ordering across preview and source/data modes: mode selector, content selector, navigation, secondary format controls/status, then external opening. Office documents retain a single preview; workbook worksheet selection precedes navigation and copy actions. Unavailable actions can be hidden without reordering the remaining actions.

Macro-enabled XLSM workbooks use the same streamed OOXML worksheet index and presentation pages as XLSX. Only worksheet values, saved formula results and presentation resources are read; VBA projects are never executed or copied into presentation workbooks. XLSM is also registered as an alternate Finder document type and included in the Excel association group.

`views/path_hint` owns main-thread native path-hint handles for clipped file-tree labels and document tabs. `native/EmbeddedPreview.swift` renders them in non-activating child panels above embedded document views, so showing a hint does not hide or recreate the reader. Hints use a shared filename/icon/path layout, wrap long paths, stay within screen bounds, and dismiss on exit, drag, click, scroll, keyboard input or window changes. Hover bounds come from GPUI layout; pending panels and event monitors are canceled when their owner is released.

### Presentation playback

The native Office toolbar offers Play Slideshow for PPT, PPTX and Keynote documents. `NativePreviewHost` keeps Quick Look attached to its original NSWindow and expands the reader over the workspace content while that window enters native fullscreen. Escape or Exit Slideshow restores the embedded frame and returns an originally windowed workspace to windowed mode. An already-fullscreen window stays fullscreen. Resize, fullscreen-exit and window-close observers keep the view and lifecycle synchronized; hiding or closing the reader cleans up its observers and key monitor. Do not use NSView fullscreen or migrate an active QLPreviewView between windows: Quick Look can assert in activate when the view returns. Document navigation, animations and embedded-media fidelity remain provider-dependent.

### PDF slideshow

Ordinary PDF reading defaults to Fit width. `ReaderPDFView` computes scale from the available scroll viewport, PDFKit page margins and rotated page geometry, including two-page spreads. Layout/page changes refit while that mode is active; zoom buttons, pinch and Actual size leave it. The localized context menu also offers Fit page. Slideshow views continue to use PDFKit whole-page autoscaling.

The PDF toolbar starts a PDFKit single-page full-screen presentation, sharing the already-open, unlocked document. Playback starts at the current page. Arrow keys, Page Up/Down, Space/Shift-Space and Home/End navigate; Escape or Exit Slideshow returns to the last displayed page with the reader's zoom mode preserved. The slideshow owns and cleans up keyboard/page observers on exit, reader hiding and reader closing. Pages render on demand without pre-generating a document-wide image array.

### Image text extraction

Image previews also provide a localized Copy Image context action and Command-C/Control-C while the image reader owns keyboard focus. Live Text selection takes precedence over image copying. PNG/JPEG keep their original file encoding for single-page files; other raster formats copy the complete decoded current page as PNG, independently of viewport crop or zoom. SVG publishes both original SVG data and a PNG rendered by an isolated, fitted WebKit preview, preserving the complete image without changing the visible reader’s zoom or scroll position. The PNG uses the reader viewport’s rendering resolution. Encoding/file access runs on a serial background queue. Reader/page changes cancel pending copies, and generation plus pasteboard-change checks prevent stale work from replacing newer clipboard contents. Clipboard transfer and receiver format support remain system constraints.

`ImageTextExtraction` uses Apple Vision locally on demand from the native image toolbar. It recognizes the current page’s already-oriented preview raster on a shared serial queue, reusing the image decoder’s working-memory policy rather than decoding the original again. A reader-owned cancellable request and generation check discard stale results on page changes, hiding, closing or starting a replacement request. A child window displays selectable plain text and Copy All; image panning stays independent. This path covers ImageIO-backed raster previews, not SVG/WebKit images. Recognition uses the current preview resolution, so small characters in very large images may require Actual size before extraction; Vision recognition is approximate and does not preserve document layout.

### Content fullscreen and Live Text

The workspace content-fullscreen action now enters macOS window fullscreen as well as hiding the sidebar and tabs. The file header is hidden; Escape leaves content fullscreen. It records whether it entered window fullscreen, so returning preserves an already-fullscreen workspace. Reader entities and preview state remain alive.

On supported macOS 13+ systems, raster image previews attach a VisionKit Live Text overlay to the existing image view. Analysis runs asynchronously against the already-oriented bounded raster; cancellation and generation checks discard old results. The overlay follows magnification and lets text selections use the system copy interaction. Hit testing forwards non-text points, or Option-drag points, to the existing image pan gesture. SVG does not use this path; older systems retain the separate Extract Text action.

### Shared slideshow input

PDFKit and Office/iWork presentations share `SlideshowInput`, a window-scoped local event monitor. Previous maps Left/Up/Page Up/Shift-Space; Next maps Right/Down/Page Down/Space; Home/End and Escape are also handled. Standard keyboard-emulating presentation remotes use the same mappings; consumer/media HID events are not mapped. An unmodified single document click advances; drags, double-clicks, native controls, floating toolbars, accessibility-exposed buttons/links and PDF link annotations are excluded. Mouse-down/up are consumed together so the provider does not also advance. PDFKit receives direct page commands; Quick Look navigation first invokes the provider's public accessibility Previous Page/Next Page button actions by semantic identifier. Disabled controls produce a boundary no-op. Providers without these controls receive canonical horizontal navigation key events without re-entering the monitor. Provider navigation remains a system dependency. HTML scripts keep their own shortcuts; no slideshow mappings are added to ordinary image/media/text reading.

During Office playback the GPUI sibling surface is made transparent and restored on exit, retaining its visibility and window routing, keeping application chrome out of the presentation while Quick Look retains the same NSWindow and view hierarchy. This does not move or recreate the preview. Content fullscreen also omits the workspace header.

The Office presentation entry also accepts F5 while the reader is visible. Navigation actions inspect the active provider's accessible control tree on demand, with cycle detection; they do not depend on file names, slide text, stored UI element indices or a preloaded list of rendered slides.

### Preview copying and document-image OCR

`native/PreviewCopy.swift` supplies Copy Preview Text and Recognize Image Text to Office/iWork and PDF toolbars. Word copies its WebKit selection or loaded body text while document JavaScript stays disabled. PDF copies its selection or current page. Other native providers expose their current text/cell tree through public accessibility interfaces; toolbars are excluded. Quick Look output depends on the provider and is plain text.

Apple Vision recognizes images locally. PDF renders only its current page within shared image working budgets; legacy Word reading can snapshot its visible viewport. OOXML/iWork embedded-image recognition uses a disk catalog and extracts one raster resource at a time, with Next image and Copy All in the result window. No whole archive expansion or total file-size cap is used. Hiding/closing cancels subprocesses and recognition and invalidates callbacks. Legacy binary Office embedded images and unsupported vector resources are not handled by this path.

PPT/PPTX/Keynote Previous and Next toolbar actions are available in ordinary preview as well as slideshow playback. Navigation uses the same provider adapter in both states; only Play Slideshow/Exit Slideshow visibility depends on playback state.

Workbook preview copying bypasses the accessibility tree and reads the active worksheet's current row/column page from the complete disk cell-value index on its serial queue. A read-only SQLite connection can be interrupted on page changes, reader hiding/closing or replacement copies. TSV output preserves empty cells and row/column order, quotes embedded delimiters and copies cached values without formatting. Worksheet names and localized internal column names do not become SQL syntax: table names are quoted, columns use positional CTE aliases, and row bounds are bound parameters. Excel and Numbers preview toolbars omit image recognition.

### Reader action surfaces

`views/workspace/reader_actions.rs` owns the GPUI document action descriptors (identity, label, icon, selection and availability). The workspace toolbar and preview context menu consume the same capability-derived list and dispatcher. Source editors retain the shared selection-aware Cut/Copy/Paste/Select All menu; preview actions are attached to content, not tabs or navigation.

`native/ReaderActions.swift` owns native reader control descriptors, menu policy and content context routing. Formats inject an ordered `ReaderControls` collection into `FloatingReaderToolbar`; Word and workbooks use semantic IDs, and existing stack-based readers use the compatibility adapter. Controls remain the live source of enabled, selected and hidden state. Button menus invoke the original control, preserving sender-dependent actions; sheet selectors project their choices into submenus. Labels are informational and never become menu commands. The toolbar retains sizing, glass appearance, overflow and hover behavior.

Native readers with toolbars get a content menu from their controls. PDF and image readers inject specialized menus through the same router and menu policy. Menus are built on demand, localized by their owning reader, exclude toolbar hits, disable AppKit context-menu plug-ins and strip foreign Services/Writing Tools entries. Routers use weak view references and remove event monitors on disposal. No menu path replaces or snapshots the reading surface. Embedded HTML pages and system playback controls retain their own interaction semantics; they do not acquire a fabricated toolbar.

## SQLite table browser

`services/sqlite/browser` queries a private WAL-aware snapshot with rusqlite. `reader/sqlite` owns persistent GPUI inputs, a searchable table/view sidebar, and a DataTable that virtualizes rows and columns. A single substring search uses bound values across every column in the full table, including columns outside the visible window. Sorting is executed in SQLite, with rowid/primary-key tie breakers where available. A persistent footer offers first/previous/next/last navigation, page entry and row counts. The 500-row page is a working-set budget, not a total-row limit; there is no application total-column cap. Horizontal scrolling requests bounded column windows. Double-clicked cells open a read-only GPUI editor with text/hex value paging.

Snapshot preparation, metadata, counts, pages and full-value windows execute outside render methods. Each retained task holds a cancellation guard; replacement or view disposal cancels its query through rusqlite's progress handler. Counts run separately so a slow count cannot block the data page. Query timeouts expose an explicit retry with a longer allowance. SQLite sources remain unchanged; recovery can write only the private snapshot. SQLite has no Swift implementation or native-preview routing. Other native formats retain their existing bridges.

Reader keyboard commands preserve focused editor/native selections. GPUI Copy bubbles to the active image or SQLite grid only when an input has not consumed it. Native toolbars share a focus-scoped keyboard router over the same enabled/visible controls for zoom, fit, page navigation, full preview copy and external opening. Image and Word own selection-aware copy handlers; Word reads only the selected text for Command-C/Control-C and generation-checks asynchronous clipboard writes. F1 lists supported commands; native shortcuts with no corresponding enabled control fall through.

`services/drawio` decodes local `.drawio` mxfile/mxGraphModel documents (raw XML or base64/raw-deflate/percent-encoded pages), resolves nested coordinates, and generates plain SVG for basic shapes, lifelines, labels and arrowed polylines. HTML labels become escaped text; no scripts or external resources are loaded. resvg renders bounded PNG pages on the loading worker, displayed by the existing GPUI image reader with page navigation and copy. Custom stencils, embedded images, rich formatting and exact draw.io routing are approximated or omitted. Source/expanded XML, group traversal, aggregate encoded previews and decoded image allocations have shared-policy budgets; failures fall back to paged XML source.

`services/opml` parses local UTF-8 OPML into a flat outline arena with parent/child indices, title, description and validated HTTP(S) feed/site URLs. It never fetches subscriptions. `reader/opml` provides a read-only, virtualized GPUI list with independent expand/collapse state and explicit open/copy actions. XML size, node count and nesting budgets are centralized; unsupported or malformed files fall back to paged source. OPML participates in existing file tabs, refresh fingerprinting and session restore.

Binary `.plist` files with the `bplist00` header are decoded by the macOS system `plutil` into a private temporary XML file before binary/text fallback. Generated source pages stay read-only, preserve the original file identity and provide bounded navigation. Conversion runs on the loading worker with process cancellation; XML plists retain ordinary text editing. No conversion writes the source file.

File-tree/tab context menus send semantic SF Symbol names through the existing bridge, retaining original item tags. Shared native reader menus decorate known actions with icons at the start of each textual row. Menus retain their original target/action, disabled and checked states; no separate icon-button row is inserted. Provider-owned menus and the GPUI toolkit editor menus retain their existing presentation.

Structured-data graphs: `services/graph` projects JSON/JSONC/JSON5/JSONL, YAML (including multi-document streams), CSV/TSV and XML into the existing local mind-map model. YAML uses serde_yaml_ng; CSV preserves duplicate headers and column positions as record arrays; XML preserves repeated elements, attributes and text nodes without resolving external entities. The graph shares the structured-input byte budget and mind-map node/depth budgets from the reader policy. Parsing runs on a retained cancellable background task. The shared structured-data toolbar in `reader/json_format` switches between the current document view and a GPUI graph, alongside JSON formatting. Ordinary editors supply current unsaved text; paged files read the complete saved file and require saving pending changes first. Returning cancels preparation, and reopening reparses current data. `reader/xmind` supplies connected cards, viewport culling, drag/trackpad panning, zoom/reset, expand/collapse, selected-node details and copy (including the focused Copy action). Scalar object fields share a card, with complete values in details. Both themes use existing tokens. No hosted viewer, network request, injected document script or source write is involved. Invalid/over-budget projections show a recoverable message and retain the original document view. This mode does not provide conversion, schema/code generation, jq queries or image export.

Manual update checks keep progress and the completed up-to-date/error status at the menu/settings entry; only an available/ready result opens the update window. Repeated checks are coalesced. The window uses a frameless app-icon/version header, a compact bordered release-notes region with a small content inset and no visible scrollbar, an automatic-download/install-on-quit preference, and skip/later/primary actions. Only release notes scroll; the surrounding window and actions stay fixed. Update preferences, release dates and utility links are omitted. Automatic downloads are enabled by default; explicit saved preferences remain respected. Skip/later dismiss the window after forwarding the existing updater command; download, draft guards, backup and installation semantics remain owned by the updater.

XMind uses a persistent bottom toolbar for frequent canvas controls. Its GPUI viewport handles native trackpad pinch gestures, preserving the content point beneath the gesture center; button zoom stays centered on the viewport. Zoom ranges from 10% to 400%. The shared XMind canvas also supplies pinch interaction to structured-data graphs.

Image-only DOCX documents use a Rust-prepared scan-page projection by default. The service detects empty body text, resolves internal image relationships in document drawing order, streams referenced resources to a private directory, and generates bounded PNG previews through the existing inline-image pipeline. Local HTML displays lazy-loaded pages at viewport width; users can still switch to native original layout. Source files are never modified. Unsupported image/metadata preparation retains the existing Word fallback.

File-fullscreen mode observes macOS window bounds and clears its reader-only state when an observed fullscreen session exits, restoring navigation and tabs. HTML native focus forwards Escape to the owning GPUI capture handler only while the preview fills the window. The WebKit document-end compatibility stylesheet suppresses inactive Reveal sections outside overview/print mode and hides 3D backfaces; source HTML is unchanged.

## Telemetry

Typed, bounded Aptabase producers live in services; the app owns consent and worker lifetime. Diagnostics feed classified errors without raw text. Workspace usage owns foreground segments; the existing native bridge registers a numeric-only Swift reader callback. Random installation identity is created on the enabled worker for cross-session format reach. The app retains a cancellable 30-second resource sampler; `native/Telemetry.swift` exposes synchronized numeric own-process Mach/getrusage/Metal counters through the existing Rust native boundary, without moving views off the main thread. GPUI resolved-command observation and workspace scroll aggregation avoid document text; native scrolling and shortcuts reuse shared reader routes. A consent generation invalidates native aggregates on opt-out/re-enable. See [event semantics, metric units and prioritization](telemetry.md).

Update-session recovery skips retired Git-only tab descriptors while preserving ordinary file and playlist tabs and remapping the active tab.
