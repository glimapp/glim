# Architecture

**English** · [简体中文](architecture.zh-CN.md) · [Documentation](README.md)

Glim is a focused file viewer for macOS on Apple Silicon and Intel. Readers share a tabbed workspace. Ordinary UTF-8 text supports basic editing and autosave; images and binary/document previews are read-only.

This reference explains responsibilities and data flow for contributors. For everyday use, start with [topics](topics.md) and the [user guide](user-guide.md).

Read module boundaries first, then workspaces and editing, file loading and readers, and storage, telemetry and updates. See the [generated inventory](reader-limits.md) for budgets and the [resources and rendering](reader-resources.md) for ownership and remaining performance work.

## Modules and data flow

### Modules and dependency direction

```text
crates/
  glim-core/src/       document, session and update values; no I/O or GPUI
  glim-services/src/   filesystem, watchers, format parsing, backups and preferences; no UI
  glim-app/src/
    app/              startup, actions, menus, locale, diagram engine and updater coordination
    views/
      workspace_window.rs  window-level ownership and workspace-tab switching
      workspace/      readers, tabs, loading, navigation, search dialog, editing and update-session restoration
      reader/         source, markup, data trees/tables, images, native previews, XMind
      explorer.rs     lazy directory tree, sticky ancestors and filename/path tooltips
      minimap.rs      document overview
native/               embedded macOS previews, settings helper and Sparkle bridge
assets/               branding, file icons, syntax queries, offline engines and bundle metadata
scripts/              packaging, signing, feed generation and focused native checks
```

Dependencies are one-way: `glim-app → glim-services → glim-core`; app may also use core directly. GPUI Kit is pinned and Cargo.lock retained. Blocking file work runs on the background executor. Render methods compose cached state, not filesystem scans or commands. Views retain their entities, subscriptions and cancellable task handles.

`views/integrations` is a retained settings entity for discovery, per-application configuration state and transient feedback. `services/integrations/discovery` combines known configuration roots, profile folders, bundle identities, supported environment overrides and user-selected files, deduplicated by tool and canonical path. `services/integrations` performs backed-up, atomic edits; TOML and JSON/JSONC retain unrelated entries and comments. It refuses same-name conflicts and edits made since discovery. `services/integrations/mcp` runs only under `glim --mcp`, before UI startup, and exposes a local stdio tool that opens an existing file or folder through macOS. It does not return file contents, access remote URLs or change client approval policies. See [app integrations](app-integrations.md) for supported clients and configuration scopes.

`services/integrations/codex` handles Codex JSON-stdin requests before UI startup, forwarding local paths through LaunchServices and validated SSH metadata through `glim://open-remote`. It bounds protocol metadata independently of document size and never executes supplied terminal commands. `app/remote_open` retains serialized validation tasks, reuses catalog connections and workspace entities, and routes file requests through the existing remote restoration/download queue. A separate retained startup task upgrades recognized local-only Codex handlers without changing editor preferences; configuration discovery remains read-only.

Reader boundaries use ordinary modules: `reader/contract` defines narrow interfaces, `reader/construction` composes them, and each view owns its state. OPML and graph views receive translation, numeric action metrics and the shared resource pool through `ReaderHost`, consuming pure core values. Extract a crate only for a concrete independent-version, dependency-isolation or cross-product reuse requirement; extension count alone is not a reason.

`minimap/geometry` computes row shapes from the editor's shared Rope and an injected resource pool, without UI entities, service access or I/O. Sequential chunk scanning constructs initial shapes; subsequent updates identify changed rows and share immutable, admitted storage blocks with earlier painted frames. `minimap` owns editor observation, navigation and painting; reader activation releases/reconstructs the optional geometry without altering editing state. Architecture checks guard the computational module's dependency boundary.

With the opt-in `reader-measurements` feature, `app/reader_measurement` composes the production `Reader` in an isolated window to measure the first readable source viewport, input and scrolling. Its observation wrapper exists only in measurement builds, without changing production reader interfaces or adding service-layer UI dependencies. Timestamps use GPUI's profiler and match actual source-subtree paint. See [resources and rendering](reader-resources.md#source-interaction-measurement) for reproducible runs and measurement scope.

`services/markdown_preview/cache` owns prepared PNG reuse with an injected resource pool and budget. Consumer lookups in the service and presentation layers have separate counters; publication and pending preparation are not counted as hits. See [cache semantics and measurement](reader-resources.md#diagram-caches-and-hit-rates).

`services/markdown_preview/disk_cache` owns persistent PNG results and their dimensions/baselines under the macOS user cache directory. Background jobs check it after memory misses and publish successful reads through the normal resource pool. Atomic files, checksums, build/environment fingerprints and capacity eviction keep this optional storage independent of document state and UI. Cache errors fall back to ordinary rendering.

`reader/diagrams` owns a bounded process-wide cache of successful display previews, independent of each view's pending queue, cancellation and retryable errors. Resident previews survive tab closure; their source keys isolate edits and formats. They remain reclaimable through the shared resource pool and are not persisted to disk.

### Local dependency patches

`vendor/gpui-base` and `vendor/gpui-pre` retain pinned upstream library sources with local changes documented in `PATCHES.md`/`GLIM-PATCH.md`. Current extensions cover file-frame panic recovery, visible-list measurement, task-checkbox editing, image dimensions and end spacing. Before removing a path patch, verify that its replacement supplies the APIs used by the app and equivalent behavior. A fixed Git revision in a patch repository can replace local sources, but introduces separate repository maintenance and build fetching; introduce that workflow only for a demonstrated need.

### Document sessions and built-in format modules

The composition boundary is `Workspace → Reader → DocumentSession + retained presentation`. `app/document_session` owns live identity, revision, path, saved-content snapshot, recovery identity and an optional shared `EditSession`. `app/edit_session` owns the editor entity, saved baseline, dirty/locked state, edit revision and subscription. Source, markup and editable pages retain that same session; a source view owns layout and minimap subscriptions. First save and window transfer preserve the editor, undo history and recovery identity. `glim-core::session` holds persisted workspace/tab descriptors independently of updater state; selection and Home-state fields default safely when reading older serialized sessions.

`ContentSnapshot` distinguishes saved UTF-8 text, derived fingerprints and untracked native sources. Ordinary saves use the saved text as their disk conflict baseline; editable pages keep their range/stamp contract. Refresh admission captures document, edit and page revisions so results cannot overwrite a newer session or page. Read-only readers have no document edit session.

`services/documents::ReadFailure` preserves filesystem error kinds before formatting diagnostics. Open and restored tabs distinguish missing files, access denial and other read failures. Unavailable views show the original path, copy-path and shared refresh/close actions; only other read failures offer diagnostic copying and issue reporting. Background refresh stays quiet for already unavailable tabs. Other refresh failures retain readable content and produce one localized notification per batch, without raw OS errors or full paths. Dirty editors remain outside refresh replacement.

`services/documents/registry` is the ordered, statically linked entry point for identification and loading. Dedicated containers precede generic archives; SQLite headers and ambiguous `.key` files retain content probes; unknown text/bytes use bounded fallbacks. Providers receive cancellation and return `documents::Content`, preserving format-specific representations. `documents/presentation` classifies text projections once: markup kind, JSON dialect, table format and structured controls. Markup/table views consume this classification without another extension whitelist.

`reader/construction` is the prepared-content factory, including paused playback during restoration. `reader/contract::ReaderView` provides retained rendering, activation and window binding. Image copying, extraction controls, playback state and persistence are optional capability traits. `reader/surface::ReaderSurface` adds refresh policy; `SurfaceEntity` adapts existing GPUI entities. `reader/opml` and `reader/xmind` consume `glim-core::outline` and `glim-core::graph`; the graph view serves both XMind and structured-text projections. Source, markup and paging share editing sessions, and workspace does not dispatch specific formats.

PDF readers opt into workspace refresh and replace the PDFKit document in the retained native controller through `glim_preview_reload_pdf`. Loading is serialized off the UI thread, writes are coalesced, and transient failures receive bounded retries while retaining the displayed document. Completion restores the page, destination and zoom, resets search without disposing its keyboard monitor, and rejects obsolete or closed-controller results. Closing the find bar returns focus to the content only when the visible bar owns focus, so background refresh cannot steal focus from another reader or settings. Refreshes requested during PDF presentation are deferred until it ends. Each `NativeReader` owns a refresh task awaiting a one-shot result. Swift owns only the channel sender context and consumes it exactly once on completion, supersession or close. A weak, document-version-checked application callback reports failures through the existing workspace notice; the watcher does not poll reader completion. PDF loading uses a shared serial native queue. C callback ownership and ABI encoding stay in `EmbeddedPreview.swift`; the native controller accepts only a Swift completion closure. A pending refresh prevents tab transfer to another window so its failure callback cannot target a previous workspace. Other non-image native documents retain their existing reload limitations.

An encrypted PDF's successful unlock password stays in the native reader's memory for background refresh and is cleared when the reader closes or a replacement is unencrypted. A changed password leaves the old document displayed; reopening the file requests the new password. Credentials are never persisted.

`reader/csv` coordinates CSV/geographic source access, paging and cancellation; its retained `csv/view` receives pure `glim-core::table::TablePage` values and emits navigation/retry requests through GPUI events. Host callbacks and display policy are injected. Structured graph output retains an admitted `PreparedGraph` owner through preparation and display; XMind state and graph layout still use their existing accounting.

`reader/sqlite` retains the private database snapshot, applied/pending query state and cancellable page/count/detail/refresh jobs. Its `sqlite/view` consumes `glim-core::table::SqlitePage`, injected translation/paging policy, status and an opaque retained detail view. The presentation emits search, table, sort, column-window, navigation, detail, retry and copy requests; it does not import services or app globals. Window binding reconnects these event subscriptions. Queued search changes received while hidden update the retained query without starting work; restoration uses that latest query. The adapter owns clipboard publication and the read-only detail editor.

`reader/books` owns chapter preparation, image entities, source-page adapters and reading-state storage. Its `books/view` consumes a borrowed catalog, pure `glim-core::books` state, injected translation/activity/policy and prepared content. Image resolution and opaque source pages are host-supplied; presentation emits preparation, persistence, link and full-text requests without service/app imports. Catalog data shares the original book and its resource lease rather than copying directory entries. Window binding reconnects application requests. Pending state is synchronously visible to shutdown before event delivery, and the independent writer coalesces snapshots and can outlive the reader.

`reader/editing` bridges document sessions to existing saving; `reader/text` handles source/preview transitions; `reader/projection` owns one optional table or JSON projection. Structured controls are retained at construction rather than created during render. Workspace coordinates navigation, tab ordering, saves and session persistence. Toolbar/context actions continue through `workspace/reader_actions` and native `ReaderActions`; data views do not acquire independent save pipelines.

`reader/find` retains the compact content-overlay search UI for source editors and rendered Markdown. It shares the vendored `SearchMatcher` for Unicode case, whole-word and regex matching, including capture expansion for editable-source replacement. Markdown matches use rendered-text offsets, range highlights and reveal operations; source matches reuse the editor's search session. Input changes are debounced, retained tasks are cancelled on close, and paged editing labels the current-page scope. `ReaderView` exposes optional `can_find`/`find` capabilities for shared toolbar and keyboard dispatch. Native `ReaderFind.swift` owns equivalent non-reflowing overlays: WebKit handles HTML/Word literal search; PDFKit asynchronously counts matches while retaining only the active selection, rescanning on navigation. Native search offers case sensitivity without unsupported regex/replacement controls. Quick Look, structured table/tree and book previews do not expose this capability.

### Reader action presets

`assets/reader-actions.json` owns the finite action registry, reusable groups, and ordered presets for each reader profile. Each action has a functional group and a fixed width in points. `scripts/generate-reader-actions.py` rejects unknown IDs, duplicates, and cyclic groups, then generates the same embedded tables for GPUI and AppKit during the build; rendering performs no configuration I/O. File classification uses the existing reader/projection capabilities, with native readers selecting their own PDF/image/Word/workbook/media profile.

Readers supply live action bindings by stable ID. `reader/controls` collects GPUI bindings and `workspace/toolbar` composes them with workspace actions in preset order; `native/FloatingReaderToolbar` does the equivalent for retained `ReaderControls`. Removing an ID from a preset hides that toolbar action; adding it displays it only if the current reader supplies the capability. Commands and selection remain owned by their reader models, including asynchronous enabled/selected changes. Toolbar configuration never stores a second copy of document mode.

Both renderers use 28-point controls, 4-point within-group gaps, narrow group separators, and 6-point vertical padding. Width is the sum of the visible preset entries; excess controls go behind the trailing chevrons. GPUI expands a compact additional row; AppKit lends the original controls to a transient popover so inputs and selectors remain usable. Transparent native toolbar margins pass through document input, while capsule hit testing resolves directly to live controls independently of decorative glass subviews. Native context menus continue to invoke those same controls.

### Background reader work

`services/work/scheduler` provides process-wide asynchronous admission, shared across windows/workspaces. SQLite receives its scheduler explicitly; production injects the global instance, while isolated test hosts construct independent instances from the same policy. `app/reader_jobs` acquires a permit before spawning a worker and keeps the permit inside the actual blocking job. Dropping a queued future removes its waiter; canceling a running UI task signals cooperative cancellation without releasing capacity before the worker exits. Each priority is FIFO. A weighted viewport, interactive, viewport, background cycle skips empty queues; visible images, GIFs and diagram batches use viewport priority. Running parsers are not preempted.

The `jobs` policy budgets document opens/refreshes, projections/pages/queries, image/GIF preparation, native preparation and diagram batches. Work is admitted per operation or GIF/diagram batch, not for the lifetime of an animation or tab. Timers, metadata-only image checks, directory browsing and persistence writes remain outside these preparation lanes. Scheduling and resource accounting do not emit per-job or periodic resource telemetry. Per-reader byte budgets still apply. `glim-core::resources` provides RAII accounting and cache reclamation, with a process-wide pool in services. Editor state, working buffers and reclaimable caches are counted separately; see [resources and rendering](reader-resources.md) for coverage and reconstruction. Third-party parser and platform framework internals cannot always be interrupted mid-call.

Watchers coalesce affected paths with `watch.pending_paths`; unknown events, errors and overflow request a rescan. Alias checks run in services on background workers. Each workspace checks refresh candidates serially, active document first, and installs each result before preparing the next. Queued changes survive loading/saving/page navigation; obsolete results are discarded and their changes requeued. Dirty documents are protected, failed replacements retain the readable view, and unchanged snapshots retain their entities. SQLite refresh-in-place is supplied by its surface rather than selected by Workspace.

Missing file aliases resolve through their nearest existing ancestor, so a removed parent does not make unrelated changes refresh the file. `DocumentSession` remembers a missing source across automatic refreshes while retaining the reader. Services check for reappearance before reading again; explicit refresh bypasses this wait. Successful refresh or save clears the missing state. This state is local to the live document and is not persisted.

`services/preview/request` and `native/PreviewRequest.swift` define version 1 of the Rust/Swift request protocol. Tagged payloads require their own fields; Swift rejects unknown versions/kinds and missing required fields. Prepared files stay owned by `PreparedPreview` until the native controller closes. Native resources initialize on demand. Rust serialization and Swift decoding share fixtures in `native/tests/fixtures`.

README/topic scenarios compose shared document reading, data inspection, media browsing and editing capabilities without adding another format dispatcher. New modules follow [Reader module contracts](reader-modules.md). `assets/format-catalog.json` declares 13 ordered providers, 232 suffixes, classifications, languages, associations and icon expectations; it generates Rust/Swift tables and the [bilingual catalog](format-catalog.md). Parsers retain content probes; icons and associations do not grant editability. `scripts/check-architecture.py` checks dependency direction, generated catalog outputs, provider order and workspace dispatch boundaries in CI. Internal modules compile with the app through explicit data and host interfaces. External installation, dynamic loading, permissions and a cross-process plugin protocol are deferred.

### Shared reader policy

`assets/reader-limits.json` is the single source for application reading thresholds, organized by reader with typed values, units, effects and descriptions. `scripts/generate-reader-limits.py` validates it and generates Rust constants, Swift ReaderLimits and embedded JSON into each Cargo OUT_DIR. `glim-services::limits` exposes the Rust values; app presentation uses that module directly, native preview targets compile the generated Swift, and the private diagram WebView receives the same value map. Builds track the policy and generator; release-tag and manual CI runs validate the complete checkout. No reader performs runtime policy-file I/O. See [the generated inventory](reader-limits.md); update it with the generator’s `--docs` option. Readers use streaming, paging or complete source fallbacks instead of total-file caps. Working budgets bound active processing, not access to complete files. The shared resource pool now provides atomic working-byte reservations. Prepared text/hex pages own their admitted text, line ranges and widest-row index; services adjust each source window to the granted bytes before allocation, and the app retains that ownership until replacement or suspension. Editable page baselines become protected state. CSV/TSV, geographic and SQLite table results use `glim-core::resources::TextRows`; services admit each row and reallocation peak before construction, and views consume the immutable owned buffer directly. CSV parser workspace and SQLite text-conversion scratch have separate reservations. Variable row windows may shorten under pressure; fixed SQLite pages fail atomically to preserve their offsets. Other tracked working owners still need admission integration; the target is not yet an aggregate ceiling for all readers.

### Scalable readers

`services/geo` streams GPX/KML coordinate pages; `services/xml` decodes XML references consistently for Geo and XLSX. `services/paged` owns editable UTF-8 pages and cancellable atomic range replacement; refresh preserves the current page and unchanged editor state. `services/streamed` recreates canceled codecs and retains a bounded rolling cache. Large cell/schema dialogs use byte windows or disk-backed source pages. Diagram blocks render in active-page batches with complete source retained. Book chapters retain navigation and use full text/hex member pages when structured rendering exceeds working budgets. Native image decoding is serialized and raster output stays within the decoded-memory budget; logical dimensions and full source bytes remain available. This is scaled preview, not region-based full-resolution decoding. SDK allocations, ZIP central-directory indexing and SQLite expression evaluation remain platform/library constraints.

Markdown preview uses TextView’s viewport-bound virtual block list rather than a natural-height whole-document widget. Table normalization only builds an AST when blank-separated pipe rows may need repair. Image and diagram discovery skip AST construction when their required syntax markers are absent. Initial preview text is enqueued after plugin configuration; diagram and formula resources update independently of the parser revision to avoid duplicate full parses. Background parsing shows a centered loading state until content is available; state completion refreshes the reader. The minimap seeks and tracks the same virtual list, and anchors use its built-in range reveal. Offscreen blocks are laid out on demand; a single large block still depends on the toolkit’s block layout implementation.

TextView's Markdown replacement parser can reuse unaffected blocks for single-line prose edits. The vendored `text/format/markdown/edit` module finds UTF-8 edit boundaries, verifies that the old top-level fragment reproduces its stored block, reparses the edited fragment and rebases subsequent source spans. Line-opening syntax, structural changes, reference definitions and opaque extension ranges retain full parsing. This changes parsing work only: snapshot copying, block cloning, preview preparation and layout invalidation remain separate costs. The parser comparison harness is described in [Resources and rendering](reader-resources.md#parser-measurement).

Structured-tree preparation produces `glim-core::structured::Tree`, retaining admission for node strings and indexes through the JSON view or graph conversion. `reader/json` coordinates jobs and recovery; `reader/json/view` is a pure presentation module with injected host operations, detail display and expansion policy. CSV and JSON use one admitted `TextSnapshot` copied directly from editor Rope chunks; unchanged input reuses the existing snapshot, and workers retain its ownership after a view is suspended or closed. Parser-owned `Value`/JSON5 workspaces remain outside this admission.

GPUI static/book/inline pixels and GIF output frames use `services::media::RasterFrame`, keeping shared admission with prepared pixels through view publication and deferred atlas cleanup. PNG decoding admits raw/conversion/workspace storage before decoder construction. GIF admits compositing/row/output buffers, reduces raster dimensions under pressure and samples directly into final pixels without a floating-point intermediate. Encoded preparation and native/framework allocations remain separate coverage gaps; [raster measurement](reader-resources.md#raster-measurement) reports owned buffers without claiming total process memory.

`reader/markup` derives its TextView style from the installed theme defaults and enables measured, adaptive table columns with horizontal scrolling when their minimum widths exceed the viewport. The local TextView patch exposes those defaults for selective overrides and adds scroll-content bottom padding; Markdown reserves 40 pixels after the final block within the same virtual list, preserving the full viewport height and shared minimap/scrollbar geometry.

The shared scheduling direction, format-specific representations, current implementation and remaining work are documented in [Resources and rendering](reader-resources.md). Diagram batches pre-analyze engine dependencies and import only required offline ESM modules; font files use memory mapping and successful raster results share a bounded in-process cache. The asset build embeds the complete module manifest in the app; no runtime project-folder scan is needed.

Markdown workspace refresh also checks referenced local still-image metadata on background workers, even when the Markdown source itself is unchanged. Changed images are decoded again; the old frame remains visible until the replacement is ready. Remote images do not participate in this filesystem refresh.

Office and workbook external-open actions resolve the current Launch Services handler at click time. When Glim owns the association, the action offers compatible applications excluding every bundle with Glim’s identifier, plus an application picker. Opening uses an explicit application URL and does not modify file associations; picker selections are checked again to prevent reopening Glim.

`services/word_preview` prepares read-only DOC/DOCX/RTF reading projections using the system textutil converter in a serialized, cancellable subprocess. Generated HTML stays on disk and is decorated with fixed IO buffers and the shared active-record budget. Font sizes become relative to readable root typography; paragraph/list emphasis is retained and the document uses the full viewport width. `native/WordPreview.swift` defaults to the full-width reading view; native Quick Look remains available for original pagination, table grids and merged cells. Its toolbar offers an explicit Reading mode / Original layout switch; reading mode uses a JavaScript-disabled, nonpersistent WebKit surface with zoom out/in, percentage and reset. Conversion/load failure keeps native layout available. Dark reading mode overrides imported text/background colors for legible text and table borders. The native controller closes before its prepared projection directory is removed. Reading view changes pagination and can differ for complex tables, drawings, embedded objects, headers/footers and typography; the original remains available. Conversion failure falls back to native layout without a total-file-size rejection. System importer/WebKit internal allocations remain framework constraints. Pages and native spreadsheet previews (including Numbers) use normal Quick Look; only slide previews retain the compact undecorated style.

Shared reader actions retain their relative ordering across preview and source/data modes: mode selector, content selector, navigation, secondary format controls/status, then external opening. Office documents retain a single preview; workbook worksheet selection precedes navigation and copy actions. Unavailable actions can be hidden without reordering the remaining actions.

Macro-enabled XLSM workbooks use the same streamed OOXML worksheet index and presentation pages as XLSX. Only worksheet values, saved formula results and presentation resources are read; VBA projects are never executed or copied into presentation workbooks. XLSM is also registered as an alternate Finder document type and included in the Excel association group.

`views/path_hint` owns main-thread native path-hint handles for clipped file-tree labels and document tabs. `native/EmbeddedPreview.swift` renders them in non-activating child panels above embedded document views, so showing a hint does not hide or recreate the reader. Hints use a shared filename/icon/path layout, wrap long paths, stay within screen bounds, and dismiss on exit, drag, click, scroll, keyboard input or window changes. Hover bounds come from GPUI layout; pending panels and event monitors are canceled when their owner is released.

## Workspaces and file operations

### Workspace and editing

The workspace registry filters expired entities and removed windows. The updater retains 300 ms polling while windows or update work are present, and polls every five seconds while windowless and idle. The local GPUI window patch rejects input queued after window removal.

Each window owns a `WorkspaceWindow` with an uncapped, ordered list of retained `Workspace` entities. Sidebar workspace tabs are flat, appear below Home, and support inline rename from their context menus. Switching workspaces retains readers, drafts, Explorer state and background saves; hidden workspaces suspend native presentation and foreground usage tracking. Window close and application quit protect drafts in every workspace. Update-session snapshots preserve workspace identities, names and window grouping. Each workspace has independent folder roots and document tabs. Adding folders appends root entries in order, including repeated paths and parent/child paths; another window can add the same folders. Explorer tracks expansion, selection and element identity per root occurrence while sharing directory data by path within the window. Top-level root context menus can remove an individual entry without deleting files or closing open tabs. Explorer emits a stable root identity; Workspace updates its roots, search scope, recent history and watchers. Removing the last root leaves open files watched independently and removes the empty workspace from recent history.

Workspace owns tabs, Explorer entities, navigation history and asynchronous loading. Newly opened files and new/recovered drafts are inserted at the left edge; session restoration preserves its saved order. File paths deduplicate opens; each live document session has a separate identity and revision. Reopening activates an existing tab/window. Finder file opens use a retained queue for every format, including unsupported files; errors stay in tabs.

Workspace presentation has three columns: workspace navigation, the file tree and the reader. `workspace/layout` owns column sizing and the file-tree toggle; `workspace/render` composes the retained entities. Navigation and the tree default to 15% and 18% of window width, with 160 px and 200 px minimum restored widths and a 35% maximum each. Both dividers resize independently, double-click restores the respective default, and dragging to 120 px collapses the column. The navigation rail retains Home and workspace icons at 48 px; the file tree disappears completely when collapsed. Its toggle sits immediately before the active workspace row’s close button, and workspace hover fills have symmetric rounded corners. ⌘B toggles workspace navigation and ⇧⌘B toggles the file tree. Selecting a workspace carries both visibility states and width ratios to the target workspace. Home hides the file column without changing its saved visibility. The selected workspace row and the file panel use the neutral content background; all workspace labels retain the normal text color. The file panel has rounded left corners and starts at the bottom edge of the document tab header. Collapsing a column gives its space to the reader without stretching the other column. File tabs move beside window navigation only when both columns are collapsed; otherwise they stay inside the content frame. `workspace/reader_actions` owns action definitions, reader capabilities, ordering, icons, labels, selection/availability and dispatch; `workspace/toolbar` renders the shared controls. Navigation and update availability remain at the upper left; file actions live in the bottom content capsule; readers expose supported capabilities rather than toolbar code maintaining a separate file-extension allowlist. Sidebar/back/forward navigation follows the Glim brand in the left title area. The content pane uses 6 px outer clearance and a 12 px radius inside the unchanged macOS window corners. A collapsed or very narrow sidebar retains the 40 px title row with 6 px clearance below it. The Glim brand and back/forward controls remain visible; narrow navigation columns use the full-width title row. The title bar also owns sidebar visibility and a search button after forward navigation; clicking it or pressing ⌘P opens a centered search dialog. Its hover hint uses the existing delayed native panel so embedded previews cannot cover it. Saving stays available through autosave, the menu and ⌘S; there is no save button or saved-status footer. These controls reuse the existing reader entities and asynchronous save operations. `app/menus` owns the three macOS menus (Glim, File and View). About, Settings and an intentionally duplicated update-check entry live under Glim; refresh remains available through its shortcut, and File → Close Window closes every workspace in the current window; ⌘, opens Settings in the current workspace. `workspace/settings` owns the theme and language selectors plus default file-type management, update checks and keyboard-shortcut help. Language selection is cached in the app and applied without reading preferences during rendering. The theme selector provides System, Light and Dark choices. Services retain the appearance preference, and the app serializes its writes; each workspace retains an appearance observer to update the theme when macOS changes while System is selected. Sidebar density and reading size are fixed, and ordinary text autosaves without a settings toggle. Start and Settings hide native reader views without disposing document tabs.

The Start page places Open Workspace…, Open File and New File in one row at a 2:1:1 width ratio, with single-line icon/label/shortcut content, a stronger brand-green workspace entry and neutral file entries. Its logo sits above the actions without a slogan. Recent workspaces include the current workspace and use compact 44 px single-column rows with aligned names and paths, a tinted current-workspace state, and muted inline icons for explicit new-window opening and history removal. Clicking a recent workspace selects or appends it in the current window; opening a new workspace prompts for a folder. Sidebar file/folder creation and folder append controls operate on the selected workspace. Workspace names in the sidebar and recent list do not show hover tooltips. Each sidebar workspace has a close icon, visible only while the pointer is over its row, that removes it only from this window, retaining recent history and protecting unsaved changes through the shared save/discard flow; closing the last workspace returns to an empty Home workspace. The window owns the shared navigation scroll handle, reveals the active workspace after selecting or opening it, and paints subtle top/bottom edge fades, soft shadows and small directional chevrons only when content remains beyond that edge. `app/workspace_sessions` caches ordinary workspace sessions by stable workspace ID, independently of update checkpoints. `services/preferences` atomically persists them in SQLite session tables; tab opens/closes/reordering, active-file changes, reader-mode changes and workspace closure update the cache through serialized background writes, drained at application shutdown. Recent-workspace opening in either window mode and startup restoration reuse ordered file/playlist descriptors, the active file and preview/source mode through `workspace/session`. Missing files remain visible as unavailable tabs. Unsaved drafts stay in the existing recovery/save-confirmation flow; generic scroll/cursor positions are not part of this session record. The same cache stores ordered workspace groups per window in SQLite window session groups, independently of recent-workspace history. Startup and reopening with no remaining windows rebuild these groups, including windows explicitly closed earlier, and restore the active workspace and its Home/document state while readers load in the background. Only the final restored selection scrolls into view. Restoration preserves recent-workspace ordering instead of promoting each background completion. Closing a workspace updates its group; closing a window retains its group for reopening. Readers retain the cache lease while showing original remote paths, and text editing, saves, trash, Finder reveal, local watching and folder playback are disabled. Transfers stream to temporary files and publish only complete downloads; cancellation invalidates the transport and the next operation establishes a fresh connection. Manual refresh remains available alongside background polling. Failed restoration keeps saved tabs for retry, and failed individual files retain unavailable tabs. Remote archives extract from the cached source into a user-selected local folder.

This initial version downloads each selected file before previewing it. It fetches referenced Markdown/HTML images but does not mirror websites, linked styles/scripts or directory-based document packages. SQLite main/WAL/journal files are fetched separately and cannot guarantee a consistent snapshot of a database being modified remotely. Cache lifetime follows the workspace/readers rather than an offline synchronization service.

Workspace loading uses the navigation icon, while individual file opens use a cancellable pending tab with the target filename. Successful opens replace that pending tab; existing-file reloads animate the existing tab icon. Local opens, Finder queues and remote downloads share this presentation, preserving the current reading surface until the new content is ready. Loading a folder animates its existing disclosure-icon box. Load indicators use the shared toolkit spinner and follow reduced-motion settings; errors remain explicit, and reader-specific preparation placeholders still provide feedback before content is available.

`workspace/remote/watch` retains a cancellable polling task for each remote workspace. Active windows check roots and visible expanded directories in rotating batches and publish only changed listings. Open files use SFTP size/mtime/mode stamps, prioritizing the active tab; referenced local images and SQLite sidecars participate, including transitions from missing to present. Changed content reloads in the background, preserves text/Markdown reading position and uses in-place refresh where supported. Failed reads keep the existing preview and tree; document identity/revision checks discard stale results. Polling pauses while the window is inactive, workspace is hidden, connection is busy or disconnected. Interval and batch budgets live in the shared reader policy. SFTP v3 timestamps have one-second precision, so same-size rewrites within the same timestamp can require manual refresh.

`services/remote/search_index` stores private SQLite path indexes keyed by connection ID, host, port, user, identity path and normalized workspace roots. SSH and SFTP share the existing OpenSSH authentication configuration. A separate, noninteractive SSH command streams NUL-delimited paths from remote `find`; unsupported shells, failed commands, malformed output or interrupted attempts continue through a persistent directory queue. Index connections use noninteractive authentication. When a dedicated connection is unavailable, password-only sessions reuse the existing authenticated connection only when idle, releasing it after one directory; foreground work may wait for that single directory operation. Background indexing never prompts to authenticate. Scans skip `.git`, include other hidden and ignored files, and do not recurse through directory symlinks. SFTP direct-child listings stream into disk-backed staging; SQLite transactions publish bounded batches and use a bounded page cache. No file content is fetched for indexing. A file lock serializes publishers for the same cache across processes; the scheduler's independent RemoteSearch lane bounds concurrent scans without taking document-opening permits.

Queries use cancellable local SQLite substring matching and paging. The UI checks revisions at the shared-policy interval and does not rerun unchanged queries. Opening a remote workspace starts the retained background index job independently of the search dialog. Existing successful indexes are immediately reused without an expiry-driven rebuild. Closing search or switching workspaces leaves indexing active; releasing the workspace or quitting cancels its jobs but retains its disk cache. The first shell enumeration is attempted once per cache, with its attempt persisted before launching. Later jobs repair or maintain the directory queue, including after restart. Already committed paths remain searchable. Manual retry wakes failed directories and the worker without clearing paths or starting a full rebuild.

`services/remote/search_index/incremental` maintains a disk-backed directory registry seeded from existing cached paths and workspace roots. Each background batch prioritizes unverified directories, then checks the oldest directory stamps through a retained independent SFTP transport. Completion checkpoints, failure counts and retry deadlines are persisted per directory; old v1 caches migrate in place. Changed or previously unknown directories stream their complete direct-child listing into a temporary SQLite table; one transaction reconciles additions, removals and file/directory replacements. Removed directories also remove cached descendants, and newly discovered directories enter the check queue. Failed listings never authorize removals; per-directory errors retain their paths and retry with exponential delays from 10 seconds up to 5 minutes, without stopping healthy directories. Connection failures also back off; a failed dedicated connection is retried after the maximum delay while the idle authenticated connection remains a fallback. Directory stamps use SFTP's second-resolution modification time, so unchanged stamps also receive eventual listing reconciliation. Reconciliation age is not a bound on delivery time: large directory counts, slow connections and backoff increase latency. This is polling, not a remote recursive filesystem watch. Cache path count is uncapped; batch, concurrency, timing and command-record budgets come from `assets/reader-limits.json`.

The search button retains its magnifying-glass outline and shows a rotating sector inside the lens during indexing or a query. Scans publish committed file counts through an atomic snapshot; a retained UI task samples it at the shared search interval without database or network I/O during rendering. The button tooltip and fixed dialog footer show preparation, scanned count, ready or automatic-retry status, including with an empty query. Background errors do not turn the search icon red or replace the result list with an error panel; their details remain on the refresh tooltip. Query failures still expose retry/copy actions. The total is unknown during traversal, so the sector is indeterminate; reduced-motion mode keeps it static. Closing the dialog leaves the button's scan feedback active until completion.

`services/content_search` scans saved UTF-8 text using case-sensitive literal matching, returning one match per line with a bounded snippet, line number and byte offset. Local traversal includes hidden/ignored files, skips `.git` and known binary/document formats, and does not follow directory symlinks. A streaming KMP scanner retains bounded read/context buffers rather than complete files or lines. `services/remote/content_search` first runs noninteractive server-side `rg`; missing `rg` or unavailable noninteractive SSH falls back to a separate SFTP transport and the existing path index. PPT/PPTX/Keynote Previous and Next toolbar actions are available in ordinary preview as well as slideshow playback. Navigation uses the same provider adapter in both states; only Play Slideshow/Exit Slideshow visibility depends on playback state.

Workbook preview copying bypasses the accessibility tree and reads the active worksheet's current row/column page from the complete disk cell-value index on its serial queue. A read-only SQLite connection can be interrupted on page changes, reader hiding/closing or replacement copies. TSV output preserves empty cells and row/column order, quotes embedded delimiters and copies cached values without formatting. Excel and Numbers preview toolbars omit image recognition.

PDF and Office/iWork remain read-only. `services/spreadsheet` streams XLSX relationships, shared strings and worksheet XML into a temporary SQLite index. ### Markdown network images and executable inspection

`app/image_http` registers a GET-only GPUI image transport. `services/inline_images` prepares static document-image previews with a maximum 2,048px edge, using the built-in macOS `sips`/ImageIO thumbnail path under a shared preparation lock. Local SVG uses the bounded raster service. `reader/pictures` retains one `InlineImageReader` per resolved static URL and activates only the current theme candidate; hidden/source-only documents cancel preparation and release their pixels. Inline static previews may lose detail when enlarged, while source files and standalone image-reader limits are unchanged. Image-atlas eviction is deferred until the current rendering window has been returned to the app, so hiding a document also evicts that window's textures.

`reader/image_detail` presents Markdown images and rendered block diagrams in a centered, fixed-size detail dialog with fit, zoom, pinch and pan controls. The vendored TextView exposes an optional `on_image_click` callback for block and inline images, including nested alert contents. Primary clicks open the detail dialog; Command-click and middle-click retain linked-image navigation. Dismissal leaves the document's scroll position intact; inline formulas remain in the reading flow.

SVG thumbnail preparation reads viewport dimensions from the XML root, sanitizes the document as a stream, and wraps it in a square SVG viewport for Quick Look so filters remain visible and wide/tall images fit without clipping. `services/executables` recognizes Mach-O, universal Mach-O, ELF and PE headers and uses object for read-only architecture, segment, section and available dependency metadata. Inspected programs are never loaded or executed. `services/documents` routes this content into the existing read-only byte reader before attempting text decoding, without separate preview windows.

### Browser HTML preview

Labels, pages and parser depth use the shared reader policy; no total document-size gate is imposed. Both native executables embed the same viewer. Popup/dialog overlays and inactive tabs hide the native surface.

The root is discovered and cached on the resource worker, so relative `../` styles/scripts in sibling project directories work without blocking native layout. Network resources use WebKit. Large HTML uses the same resource worker to stream the original document instead of building a full editor snapshot. This browser path is separate from Markdown's static inline-HTML handling and the isolated offline diagram renderer.

Book chapters, static preview PNGs and read-only pages use reader-owned resource leases and cancellation. ## Local data and diagnostics

### Diagnostics and file failure isolation

`glim-services::diagnostics` owns a bounded background log writer under `~/Library/Logs/Glim/`. Logs use local calendar dates, rotate before 8 MiB per file and retain at most 14 log files (including current-day segments); startup and rotation prune older segments. The bounded queue accepts ordinary messages without blocking rendering; panic records request a synchronous flush with a two-second acknowledgement timeout. Logs include startup/version, file open/read/reader initialization, tab activation, saves and toolkit Info/Warn/Error messages. Panic records include the owning file path, phase, thread, source location and forced backtrace; file contents are not logged. Ordinary queue overflow may drop diagnostic events.

`reader::boundary` attributes the complete lazy file layout/prepaint/paint subtree to a file. The panic hook quarantines that path for the current process. A local patch of pinned `gpui-pre` 0.3.8 (`vendor/gpui-pre/GLIM-PATCH.md`) catches acknowledged file draw panics before the macOS callback, restores entity leases/update depth and the layout engine, discards partial frame state and drawing stacks, and forces a clean frame. The failed file becomes an error page with its full path, retry and log-folder controls; other tabs and unsaved editor entities stay alive. File read and reader-construction unwinds become file failures. Retry is explicit; quarantine resets at app restart. Abort-mode panics, OOM, stack overflow, native exceptions and unrelated app panics are outside this unwind boundary.

### Telemetry

Usage and diagnostics consent are independent values in `services::telemetry::Consent`, atomically persisted by preferences. The app owns worker replacement, cancellation and serialized saves; the workspace settings view presents the controls and save failure/retry. Producers enforce the channel boundary before queueing. The synchronized native bridge separately gates usage aggregation and error callbacks. A diagnostics-only worker neither reads installation identity nor posts analytics; with both channels disabled no telemetry worker runs. `scripts/telemetry-activity-report.py` derives observed active installations and return from opted-in foreground segments, keeping missing observations unknown.

Typed, bounded Aptabase producers live in services; the app owns consent and worker lifetime. Diagnostics feed classified errors without raw text. Workspace usage owns foreground segments; the existing native bridge registers a numeric-only Swift reader callback. Random installation identity is created on the enabled worker for cross-session format reach. Routine telemetry focuses on feature usage and outcomes; per-job events, periodic resource sampling and hardware profiles are absent. SSH opens and restored reader capabilities identify their storage and trigger; configuration actions, find entry and embedded-image use have explicit events. GPUI resolved-command observation and workspace scroll aggregation avoid document text; native scrolling and shortcuts reuse shared reader routes. A consent generation invalidates native aggregates on opt-out/re-enable. See [event semantics, metric units and prioritization](telemetry.md).

Update-session recovery skips retired Git-only tab descriptors while preserving ordinary file and playlist tabs and remapping the active tab.

### Application database

`glim-services::storage` owns `~/Library/Application Support/Glim/glim.sqlite3`, schema versioning (`user_version`), foreign keys, a busy timeout, WAL journaling and FULL synchronous commits. Only services perform database I/O, before GPUI startup or on retained background tasks. Core session models remain I/O-free. Settings and installation identity are individual rows; recent workspaces, ordered roots, Explorer expansion, window/workspace sessions and ordered tabs use relational tables. Format-specific book state (including bookmarks) and versioned one-time update checkpoints use JSON payloads inside database records. Draft text and metadata use dedicated rows, with OS locks retaining process ownership. Session and history replacements use transactions; multi-query session reads use a consistent snapshot.

First startup imports supported legacy preference/session files and book records in one transaction. A failure rolls back schema and data together and leaves source files available for repair. Only after commit are imported files moved into `LegacyMigration`, a single recoverable migration archive; subsequent launches never reimport them. Draft recovery imports abandoned legacy sessions while holding their OS locks and records each source in the same transaction to prevent duplicate recovery after a crash. Active sessions remain untouched. Unknown legacy files are preserved. Schema v2 removes the standalone `imported_files` table: pending source checkpoints temporarily use `records(kind='migration-source')` and are deleted after their source is archived or absent. Active legacy draft sessions retain their checkpoints until recovery completes. Schema v3 adds active-workspace and Home-state flags to session rows, preserving existing roots, tabs and recent ordering in one transaction. Newer unsupported database schemas are rejected.

Application bundles, update ZIPs and SHA-256 receipts, logs, session lock markers and user documents remain filesystem artifacts. Update backup preparation retains only one verified archive/receipt pair; local development installation retains up to two bundle backups. Public releases remain independent of local packaging.

SQLite reader refresh compares the main database, WAL and rollback journal stamps captured when its private snapshot was created. Neighboring file activity and SHM coordination changes do not reload the database. Changed snapshots are prepared in a retained cancellable background task and published into the existing grid without clearing its rows first, retaining the table, filter, sort and page where the schema permits. Refresh errors preserve the previous readable snapshot; explicit refresh bypasses the source-stamp check.

### Archive browser and extraction

`services/archive` routes ZIP, TAR and compressed TAR aliases, 7z, RAR, CAB, CPIO, AR, XAR, ISO9660 and LHA through the same `reader/archive` virtualized directory browser. Standalone compressed streams appear as a single decompressed file. ZIP retains raw UTF-8 filename detection and legacy decoding. Other containers use the embedded `native/Archive.c` helper linked to macOS libarchive; metadata streams through a temporary JSON-lines index. Services own helper execution and cancellation, killing and reaping it before cleanup. Zstandard and LZ4 use bundled Rust decoders into temporary files, avoiding optional command-line codecs. Buffer sizes come from the generated shared policy. Archive indexes and solid-block decoding retain library allocation constraints; file payloads are not loaded as a whole. Encrypted, multipart and unsupported codec variants report errors.

The shared reader actions expose extraction and cancellation in the toolbar and content menu. Services extract into an isolated staging directory, validate member paths and links, reject special filesystem entries, preserve executable permissions, and publish a uniquely named folder without replacing existing directories. Native extraction enables libarchive's secure path/symlink and no-overwrite options; mtree descriptions are rejected. Failure or cancellation removes staging output. Workspace opens successful output as a separate new workspace, retaining the source workspace. Compound suffixes such as `.tar.gz` are removed from the output folder name.

### Platform, preferences and update boundaries

`native/FinderSync.swift` is a sandboxed Finder Sync extension packaged at `Contents/PlugIns/GlimFinder.appex`. It supplies a direct folder context-menu action, without badges or directory scans, and delivers percent-encoded `glim://open-workspace?path=...` requests. `app/finder_integration` retains a serialized background task for directory validation and recent-session lookup; application routing selects an existing matching workspace or opens an independent workspace in the active Glim window. It never appends the selected folder to another workspace. The native `FinderIntegration` bridge opens Apple's extension-management interface from Settings; startup does not show a setup dialog. Finder action callbacks resolve their selection from the controller at click time instead of relying on represented objects crossing Finder's process boundary. Activation remains the user's choice and menu ordering belongs to Finder. The app and its extension are signed inside-out, with sandbox entitlements on the extension only.

The maintained workspace uses GPUI on macOS Apple Silicon and Intel with ⌘ shortcuts. Swift provides native previews and default file-type settings; diagrams use system WebKit. Windows application/service branches have been removed; the build script explicitly rejects non-macOS targets.

macOS bundle identity remains `io.github.jony4.glimpse` for compatibility. Preferences use `~/Library/Application Support/Glim`, with legacy Glimpse fallback where implemented. Locale dictionaries are embedded; document text and technical diagnostics are not translated. Each documentation topic has English and Simplified Chinese counterparts.

`glim-core/update` defines snapshots, modes, activity guards and session values. `services/updates` verifies/copies backups and writes/consumes bounded session checkpoints. `app/updates` owns one global `UpdateState`, task handles, editing locks and exit-generation checks; `views/updates` renders a reusable centered window. Menu/About/titlebar entries share that state. Finder opens arriving during exit preparation withdraw approval and preserve the file request.

The macOS `macos-updater` feature connects `app/updater_bridge` to Sparkle 2.10.0 in `native/Updater.swift`. Its custom user driver delegates install approval to Rust. The bridge adds the missing cancellable termination method to the fixed GPUI delegate without replacing it; incompatible future delegate contracts disable updating. Sparkle handles signed downloads, extraction, permissions and replacement. Unconfigured builds offer manual downloads. Only the two Mac architectures receive signed update feeds.

### Update interface

Manual update checks keep progress and the completed up-to-date/error status at the menu/settings entry; only an available/ready result opens the update window. Repeated checks are coalesced. The window uses a frameless app-icon/version header, a compact bordered release-notes region with a small content inset and no visible scrollbar, an automatic-download/install-on-quit preference, and skip/later/primary actions. Only release notes scroll; the surrounding window and actions stay fixed. Update preferences, release dates and utility links are omitted. Automatic downloads are enabled by default; explicit saved preferences remain respected. Skip/later dismiss the window after forwarding the existing updater command; download, draft guards, backup and installation semantics remain owned by the updater.
