# 使用统计技术说明

[English](telemetry.md)

普通用户请先看[隐私与联网说明](privacy.zh-CN.md)，了解开关、上传范围和本地记录。本文供维护者核对事件字段、指标口径和离线分析；安装数、下载量和使用人数分别统计。

设置将使用统计与错误诊断分开。类型化事件在入队前按所属通道检查授权：使用统计控制前台片段、原生输入聚合、功能事件与安装标识；错误诊断控制 Rust／原生错误分类、panic 与重复聚合。仅错误诊断模式只发送专用错误接口，不发送使用事件、持久安装标识或统计 health 事件。更改选择会取消旧后台任务、清空待发送数据并使原生聚合失效。两项都关闭时不启动遥测任务，也不请求远程配置。

`telemetry-consent` 设置原子保存两个选项。缺少新设置时，旧 `telemetry` 明确保存的值作为两个开关的初值；没有记录过选择时默认开启两个通道，不显示启动弹窗。读取失败时全部关闭。保存时同步维护旧总开关，仅在两个新开关都开启时写 true，防止降级后重新启用已拒绝的通道。保存失败会在设置中显示并允许重试，当前选择仍对本次运行有效。

仅使用统计获准的后台任务读取或创建随机 128 位安装标识 `installation_id`，保存在 Glim 应用数据库的 settings 表，不读取账号、硬件身份、路径或文档内容。该标识可以跨会话关联记录，属于假名化标识。它跨启动、关闭后重新开启保持一致；缺少该设置记录时会生成新标识。身份存储不可写时省略标识，避免把每次启动误算成新人。

按 `installation_id` 去重得到的是安装数，作为使用人数的近似。换电脑、清除应用数据、关闭遥测和发送失败都会影响结果。Aptabase 内置会话数不能直接叫人数；跨会话去重需要导出分析或支持 distinct 的自定义查询。

## 活跃安装与观察到的回访

指标统一称为**开启使用统计的活跃安装数**。以正数 `foreground_segment.duration_ms` 对应的安装标识去重，包含主页、设置和未命名草稿。仅启动、后台通信、诊断和下载不证明前台使用；前台停留仍可能包含空闲。没有上报的状态是未知，不能算作流失；关闭使用统计后没有替代心跳。

```sh
python3 scripts/telemetry-activity-report.py events.jsonl --app-id <正式应用ID> --output-dir activity-report
```

报表支持与格式报表相同的导出格式和私有安装排除列表，输出 `active-installations.csv`、`observed-return.csv`、`summary.json`。摘要统计截至 UTC+8 的 `--as-of YYYY-MM-DD` 当日、近 7 个和近 30 个日历日的去重活跃安装数，默认截至各应用最后导出日期。跨天数值对整个窗口去重，不相加每日数量。需导出完整目标区间；摘要记录实际观察到的导出日期，不据此保证数据完整。缺少标识的记录单列，不补造身份。schema 4 之前的前台记录沿用旧总开关，schema 4 要求 `usage_statistics=true`。

回访队列以导出中首次观察到的前台日期分组，不推断安装日期；D1／D7／D30 统计对应日期实际观察到的回访，其余成员状态未知。比例表示这份已开启统计的导出数据中的观察回访率，不能证明全部安装的留存或流失。开发与正式数据必须分开查询。Aptabase 原生会话指标保持原义；活跃安装数使用该报表或等价的后台 distinct-ID 查询。

## 开发与正式渠道

Aptabase 的 `systemProps.isDebug` 按构建来源区分。本地 `cargo run`、本地优化构建和本地 `.app`／DMG 打包统一上报 debug。只有官方仓库推送 `v*` 标签的工作流，在 `GLIM_DISTRIBUTION=github-release` 且使用优化 Cargo profile 时编入 release 路由；手动工作流、普通分支和 fork 保持 debug。渠道固定在二进制内，移动应用或修改运行时环境变量不会改变它。CI 在打包前核验可执行文件。`/Applications/Glim.app/Contents/MacOS/glim --build-info` 只输出渠道和版本，不启动应用、不读取安装标识、不发送遥测。

事件另带 `telemetry_environment=debug|release`。历史 `system_profile.debug_build` 表示编译器是否启用 debug assertions，与遥测渠道独立；当前构建不再发送该事件。此前本地优化包被计入 release，修改不会重分类历史数据；分析旧导出时需排除已知开发安装 ID。

正常升级、替换应用包、关闭后重新开启遥测，以及开发／正式渠道切换，都复用应用数据库中既有的 `telemetry-installation-id`；版本、build 和渠道均不参与该键。清除应用数据或换设备可能产生新安装标识，会话标识独立轮换。安装数仍不等同于人数，当前没有基于账号的跨设备合并。回归覆盖数据库升级／重启、并发首次启动和只读／无效存储，不重建已有身份。

## 哪些格式最值得优化

以 `file_open` 为新打开尝试的权威事件，包含格式、格式族、成功/失败和耗时。已经打开的标签切换只记 `tab_activated`。后台刷新可能产生 `reader_opened`，不能据此累计主动打开次数。文件夹单独记录 `workspace_open`。常见无后缀配置文件映射到固定类别，未知后缀统一为 `other`，不上传用户自行定义的名称。

在相同版本和时间范围内，先按尝试打开的去重安装数排序，再看打开次数、失败率、原生加载失败数、P50/P95 耗时和前台停留。失败的打开也计入需求覆盖量，避免坏掉的格式从需求榜中消失。`file_open` 的成功可能只代表完成格式识别和初始读取，原生准备还需检查 `native_load`；这些耗时不等同于首屏完全绘制或原生播放成功。格式白名单尚未囊括所有受支持格式；`other` 偏多时应扩充固定分类，不能直接上传任意后缀。

提供离线报表脚本：

```sh
python3 scripts/telemetry-format-report.py events.json --output formats.csv
```

输入支持 JSON 数组、JSONL、CSV，字段为 `eventName`/`event_name`、`sessionId`/`session_id`、`props`/`properties`（CSV 中属性为 JSON 字符串）。脚本按去重安装数排序，输出打开次数、会话数、失败率、耗时分位数、原生加载失败、前台秒数和缺少身份的打开数，并按事件序号去除重复导出行。覆盖率分母为这份导出中出现的全部可识别安装；应导出同一时间范围的完整事件，仅导出文件事件会得到文件使用者内部覆盖率。时间与版本在导出时先筛选。脚本不会自动获取线上数据，旧版只有启动事件的数据无法补算历史格式榜。

## 如何判断下掉或扩展

功能使用率应以具备该能力的会话为分母：参考 `reader_opened` 的 `can_preview`、`can_edit`和格式。能力可用不代表用户看到了隐藏工具栏。

覆盖人数多且失败率/耗时高，优先修可靠性；覆盖多且频繁切换预览、搜索或分页，值得检查显示和操作体验。人数少但停留长，可能是有价值的专业场景。前台停留包含发呆时间，不能当作注意力或满意度。下掉功能需结合多个版本的机会校正使用率、停留、维护成本和反馈；没有实现自动删功能。

## 隐私、错误与完整性

不上传文档内容、文件名、完整路径、搜索词、数据库/表/列名、URL、原始日志/错误/panic 文本。错误仅含分类、应用源码文件名/行号、组件/阶段、固定指纹、系统错误码和最多三条应用/GPUI panic 符号。最近操作上下文只有事件名；完整诊断保留本地。强制退出或崩溃可能来不及发送。

失败率以操作结果为准。同一次故障可能同时触发 `operation_failed` 和 `error_logged`，不能把诊断事件相加当失败次数。同指纹错误一分钟内去重，后续刷新或正常退出以 `error_repeated.occurrences` 聚合；有限指纹表淘汰可能丢失重复细节。`telemetry_health.errors_suppressed` 是压缩信息，不能再与 occurrence 相加。

类型化的阅读取消记录 `result=cancelled`，不发送 `operation_failed`，统计失败次数时排除取消。SQLite 打开失败附带格式、固定的 snapshot/recovery/schema 阶段、文件系统／快照／SQLite 错误分类，以及可用的 SQLite 数字扩展错误码；数据库名称、结构及错误原文保留本地。

诊断发送到 Aptabase 专用 `/api/v0/error` 接口，写入 Errors 页面；普通统计使用 `/api/v0/events`。覆盖 `error_logged`、`operation_failed`、`app_panicked`、`native_reader_error`、`updater_error` 和 `error_repeated`。报告仅由既有脱敏字段构成：分类、组件／操作／阶段、源码位置、指纹、格式、有符号错误码和有限 panic 符号。摘要包含 `occurrences`（首次报告为 1）；一条聚合对应 Errors 的一行，不按重复次数逐行发送。聚合保留原始 `error_event`，包括 panic 的严重程度。panic 标记为 `fatal`／`unhandled`，其他诊断为 `error`／`handled`。顶层 `isDebug` 与普通统计采用相同构建来源规则；历史统计事件不会回填 Errors。

错误通道使用独立的 128 条内存队列和指数退避。既有可取消后台任务每轮最多发送一条错误，遵守错误诊断开关和退出生命周期。网络失败、HTTP 408／429 和服务端失败保留报告待重试；其余 HTTP 4xx 丢弃该报告。退出时在应用既有刷新期限内尽力发送。队列满时淘汰最旧待发送报告；同时开启使用统计时，通过 `telemetry_health.error_reports_dropped` 和 `error_upload_failures` 披露丢失与请求失败。仅错误诊断模式不向统计接口发送这些计数。服务器确认丢失后重试可能产生重复记录，不保证恰好一次送达。

内存队列最多 256 条、每批最多 25 条、约两秒刷新；支持取消、有限退出等待和指数退避。没有磁盘发件箱或原始日志上传。断网、锁竞争、队列淘汰会丢事件，后续成功发送时用 health 事件披露。长时间运行每天轮换 Aptabase 会话，安装身份保持稳定；网络发送失败不会递归产生错误埋点。

## 功能使用采集（schema 4）

统计事件带 `schema_version=4`、`usage_statistics=true`、架构和操作系统 build，Aptabase 系统字段带 macOS 版本、应用版本/build、语言和 SDK 版本。常规上报不再采集硬件配置、CPU／内存／GPU 资源、缓存计数或逐任务排队耗时，停止发送 `reader_job`、`resource_sample`、`system_profile`。本地资源准入、缓存回收、取消机制和性能测量工具独立保留。

主动打开文件的覆盖率看成功的 `file_open`；阅读器可用能力看 `reader_opened`，包含恢复的标签。`reader_opened.trigger=open|restore` 区分新打开与恢复，`storage=local|ssh` 区分本地与 SSH，远端阅读器的 `can_edit=false`。SSH 的 `file_open` 记录主动打开的格式、结果和耗时；成功的自动／手动刷新不重复计为打开文件。带 `storage=ssh` 的 `workspace_open` 记录打开或恢复远端工作区，由 `trigger` 区分；恢复加载路径也用于最近工作区与外部请求。前台停留事件也标注存储类型。应用驻留时间与事件总数不等于使用时长；文档前台时间是占用时长，可能包含发呆。

`ssh_connection` 记录测试、保存、连接、删除的结果；`integration_configured` 记录应用类别和关联／取消关联结果，仅由用户主动操作产生，实例扫描和自动配置迁移不计入。`reader_feature.find_opened` 覆盖源码及文本预览查找；原生 `find_opened` 覆盖 PDF、Word、HTML 的查找，包括直接使用快捷键。替换操作只记录单个／全部标记。内嵌图片记录打开详情，以及每次打开后至多一次的缩放使用，包含手势缩放。不会上传搜索词、替换文本、主机名、用户名、私钥路径、连接名称或配置路径。

### 滚动与快捷键

`reader_scroll` 汇总一次连续滚动，约 700 毫秒无输入结束，最长连续段约 10 秒；记录输入事件数、持续毫秒和横纵位移。GPUI 记录 points、lines×100、正负方向事件数；原生记录 delta×100 与明确的 `delta_unit`。这是滚轮/触控板输入，不能等同于内容实际移动、滚动深度或读完比例；到达边界仍可能收到输入。GPUI 由已有文档捕获路径收集，原生复用现有 `ReaderContextMenu` 路由，重叠原生路由按事件对象去重；不改变滚动行为。原生段只保证存活期间定时刷新，强退可能丢失尾段。原生页面的方向仅保留横纵绝对位移，GPUI 另有正负方向计数。两套捕获能力不同，不能把原始位移数值直接混算。

`shortcut_used` 收集 GPUI 已解析出的静态命令名、修饰键、固定白名单命令键标记及活动格式，覆盖应用操作、书籍翻页、文件树导航，以及编辑器已解析的复制/剪切/粘贴、撤销/重做、查找和光标命令。普通字符输入不上传文本；未知绑定键为 `other_bound_key`。命令键标记用于区分同一操作的 Space/PageDown 等绑定。GPUI 拦截器或原生视图提前消费的键不会进入这个观察器。

`native_shortcut_used` 由已有原生快捷键处理路径收集，含静态阅读器/动作、Command/Control/Option/Shift 和已识别命令的物理 `key_code`；物理键码不代表当前键盘布局产生的字符。覆盖原生复制、全选、缩放、适配、实际大小、预览文本复制、OCR、外部打开和翻页。原生操作的 `input_source` 为 pointer/keyboard/menu/unknown；异步结果和状态观察不推断用户来源。系统自带菜单、Quick Look、WebKit 或 AVPlayerView 内部未经过这些处理路径的快捷键不保证覆盖。

| 媒体 | 播放/暂停调用、上下项目、播放失败、观察到的播放/等待/暂停状态、静音状态、合并后的音量值、约每 30 秒的播放位置与已知总时长 |
| 工作区/文件树 | 阅读全屏实际变化、带格式上下文的工具栏调用、右键菜单动作（新建、播放目录/随机播放、打开、Finder 定位、复制相对/绝对路径、废纸篓、移除目录）；仅动作类别，不上传路径 |

`reader_feature` 为阅读器操作尝试，不能统一当作完成；部分操作按阅读器类型归类，未附精确后缀时不要猜测。例如原生 Word 操作可能合并 doc/docx，书籍操作可能合并 epub/fb2；精确格式覆盖人数仍以 `file_open` 为准。原生 `semantic=invocation/outcome/observation` 区分调用、结果和状态观察。OCR 完成附观察结果数量和耗时，不上传识别文字；没有找到文本可以是成功结果。复制未找到可复制文本以静态错误码 2 表示。媒体播放位置与预期相差超过两秒时记 `playhead_jump_observed`，这是启发式观察，缓冲或系统时序也可能触发，不能当精确的用户拖动次数。音量变化合并 400 毫秒内连续更新，不逐帧发事件。

关闭遥测也会停止原生收集，并轮换内存聚合代次；重新开启不会把之前的滚动或播放位置片段补发。所有数据沿用有界队列、去重及丢失计数规则，不能保证强退、断网或极高频操作下逐条送达。API 支持与操作分发的静态接入已完成；实际交互覆盖需在 macOS 手动验证。

### 明细导出

默认 `timeline.csv` 和 `actions.csv` 排除历史 `reader_job`、`resource_sample`、`system_profile`；排查旧版本时可传 `--include-performance`。历史资源样本仍进入 `resources.csv` 与 `resource-peaks.csv`，当前构建不产生新样本。

```sh
python3 scripts/telemetry-detail-report.py events.json --output-dir report
```

生成 `timeline.csv`（逐条事件及完整安全属性）、`actions.csv`（事件/格式/阅读器/动作/来源/结果分组）、`shortcuts.csv`（命令与组合键排行）、`resources.csv`（活动格式下主进程指标的样本数、P50/P95/最大值）。支持与格式榜相同的 JSON/JSONL/CSV 输入；相同会话与序号的导出重复行只算一次。时间线保留导出顺序，可按会话与事件序号查看链路；不是可靠的全局因果排序。先在导出中筛选版本与时间范围，再比较报表。安装数缺失时不会伪造人数。

## 命令行过滤与有效使用口径

两个报表脚本支持 ClickHouse JSONEachRow/CSV 的 string_props、numeric_props、os_version、app_version 列，以及 .jsonl.gz 流式读取。用 --app-id 选择生产应用，避免混入其他产品和 DEBUG；用 --exclude-installations-file 读取本地 UTF-8 安装 ID 清单（每行一个，允许 # 注释），也可重复传 --exclude-installation-id。个人 ID 清单放在仓库之外；缺少身份的事件保持未归属。

格式报表统计成功打开安装数、在导出范围内跨 UTC+8 自然日成功打开的安装数，以及源码回退次数。跨日观察不等于 cohort 留存率。详细报表生成 activity.csv，按安装与 UTC+8 日期统计打开次数、成功次数、有打开的会话数和文档前台片段秒数；resource-peaks.csv 保留每个安装各指标峰值对应的时间、版本、格式和窗口/标签数。Aptabase 会话时长含后台驻留，旧版导出的总事件量含大量资源采样，不用它们替代有效使用；前台片段仍包含空闲，不能证明阅读完成。

XMind 解析或工作预算失败但源码分页成功时上报 reader_fallback，固定 reason 区分 container/content_entry/decompression/json/xml/structure/unknown，preview_budget 标识工作预算回退。file_open 成功不保证思维导图渲染成功，需同时查看回退事件。operation_failed 包含 reader_stage 并纳入错误签名，均不上传文档或错误原文。telemetry_health 包含可用的安装 ID、schema、架构、系统构建和独立序号；error_repeated 聚合使用新序号。历史缺失 ID 无法补算。

`process_session_id` 在 Aptabase 满 24 小时轮换 `sessionId` 后仍保留本次启用遥测的会话标识，`session_uptime_s` 记录事件采集时的单调运行时长；遥测重启或关闭后重新开启都会重置。它们用于关联同一进程的持续使用，不能代表人数或证明主动回访。`foreground_segment` 和当前阅读器上下文增加 `untitled`，区分草稿与文件阅读。统计有效使用安装时需包含草稿创建、编辑与保存，仅依赖成功 `file_open` 会漏掉纯记事本使用。

`tab_closed.reason=preview_replaced` 区分连续浏览替换与主动关闭。`update_phase_changed` 在使用统计获准时仅记录固定阶段；`updater_error` 在错误诊断获准时独立记录固定 `error_stage`、固定 `error_kind` 和有符号数字 `error_code`。不上传原生错误消息、网址或路径；错误码仅提供诊断线索，不能完整解释失败原因。

更新诊断还包含白名单 `error_domain`／`underlying_error_domain`（sparkle/url/cocoa/posix/other/none）及有符号 `underlying_error_code`。原阶段停留在 idle/current 时，尽可能按 Sparkle 错误码范围确定阶段。缺少 URL 错误的下载失败归为 download；URL 取消和用户取消安装不进入错误通道。不上传任意 NSError 域名或 userInfo。
