# 使用统计与格式优化

[English](telemetry.md)

沿用设置中的遥测开关。开启时发送功能事件和脱敏错误；关闭立即取消发送并清空队列。仅在启用的后台任务中创建随机 128 位安装标识 `installation_id`，保存在 Glim 偏好目录，不读取账号、硬件身份、路径或文档内容。标识跨启动、关闭后重新开启保持一致；删除偏好标识文件后会生成新标识。偏好目录不可写时省略标识，避免把每次启动误算成新人。

按 `installation_id` 去重得到的是安装数，作为使用人数的近似。换电脑、重装、关闭遥测和发送失败都会影响结果。Aptabase 内置会话数不能直接叫人数；跨会话去重需要导出分析或支持 distinct 的自定义查询。

## 哪些格式最值得优化

以 `file_open` 为新打开尝试的权威事件，包含格式、格式族、成功/失败和耗时。已经打开的标签切换只记 `tab_activated`。后台刷新可能产生 `reader_opened`，不能据此累计主动打开次数。文件夹单独记录 `workspace_open`。常见无后缀配置文件映射到固定类别，未知后缀统一为 `other`，不上传用户自行定义的名称。

在相同版本和时间范围内，先按尝试打开的去重安装数排序，再看打开次数、失败率、原生加载失败数、P50/P95 耗时和前台停留。失败的打开也计入需求覆盖量，避免坏掉的格式从需求榜中消失。`file_open` 的成功可能只代表完成格式识别和初始读取，原生准备还需检查 `native_load`；这些耗时不等同于首屏完全绘制或原生播放成功。格式白名单尚未囊括所有受支持格式；`other` 偏多时应扩充固定分类，不能直接上传任意后缀。

提供离线报表脚本：

```sh
python3 scripts/telemetry-format-report.py events.json --output formats.csv
```

输入支持 JSON 数组、JSONL、CSV，字段为 `eventName`/`event_name`、`sessionId`/`session_id`、`props`/`properties`（CSV 中属性为 JSON 字符串）。脚本按去重安装数排序，输出打开次数、会话数、失败率、耗时分位数、原生加载失败、前台秒数和缺少身份的打开数，并按事件序号去除重复导出行。覆盖率分母为这份导出中出现的全部可识别安装；应导出同一时间范围的完整事件，仅导出文件事件会得到文件使用者内部覆盖率。时间与版本在导出时先筛选。脚本不会自动获取线上数据，旧版只有启动事件的数据无法补算历史格式榜。

| 范围 | 事件及可分析内容 |
| --- | --- |

| 编辑与保存 | 草稿创建、首次编辑、手动保存请求、自动/显式保存结果、首次落盘、保存对话框取消、格式拒绝、关闭时保存/丢弃/取消、恢复、移到废纸篓 |
| 导航与操作 | 添加目录、搜索结果数量、预览模式、自动换行、阅读器工具操作、Markdown 待办完成状态 |
| 数据与书籍 | CSV/SQLite 分页请求及加载结果、数据库表切换、分页文本模式、书籍加载/翻页/章节/书签 |
| 图表 | `diagram_render`：固定类型和渲染结果，按完成计算，不逐帧上报 |
| 原生阅读器 | 图片复制/OCR/缩放/分页，PDF 适配/布局/演示/导航，Word 模式/缩放，表格分页/工作表，字体选择，媒体播放，演示/外部打开；仅数字枚举跨 Swift/Rust 边界 |
| 设置与更新 | 设置/快捷键打开、主题/语言、更新操作，编译启用更新器时的状态变化 |

分页/加载事件包含初始化与刷新，代表工作量，不能都解释成独立主动点击。工具栏意图和实际状态变化是同一操作的不同阶段，不能相加。原生按钮事件代表调用，不保证操作完成；保持原有按钮目标、菜单和快捷键分发。

## 如何判断下掉或扩展

功能使用率应以具备该能力的会话为分母：参考 `reader_opened` 的 `can_preview`、`can_edit`和格式。能力可用不代表用户看到了隐藏工具栏。

覆盖人数多且失败率/耗时高，优先修可靠性；覆盖多且频繁切换预览、搜索或分页，值得检查显示和操作体验。人数少但停留长，可能是有价值的专业场景。前台停留包含发呆时间，不能当作注意力或满意度。下掉功能需结合多个版本的机会校正使用率、停留、维护成本和反馈；没有实现自动删功能。

## 隐私、错误与完整性

不上传文档内容、文件名、完整路径、搜索词、数据库/表/列名、URL、原始日志/错误/panic 文本。错误仅含分类、应用源码文件名/行号、组件/阶段、固定指纹、系统错误码和最多三条应用/GPUI panic 符号。最近操作上下文只有事件名；完整诊断保留本地。强制退出或崩溃可能来不及发送。

失败率以操作结果为准。同一次故障可能同时触发 `operation_failed` 和 `error_logged`，不能把诊断事件相加当失败次数。同指纹错误一分钟内去重，后续刷新或正常退出以 `error_repeated.occurrences` 聚合；有限指纹表淘汰可能丢失重复细节。`telemetry_health.errors_suppressed` 是压缩信息，不能再与 occurrence 相加。

内存队列最多 256 条、每批最多 25 条、约两秒刷新；支持取消、有限退出等待和指数退避。没有磁盘发件箱或原始日志上传。断网、锁竞争、队列淘汰会丢事件，后续成功发送时用 health 事件披露。长时间运行每天轮换 Aptabase 会话，安装身份保持稳定；网络发送失败不会递归产生错误埋点。

## 细粒度操作与资源指标（schema 3）

普通事件带 `schema_version=3`、架构、操作系统 build，Aptabase 系统字段带 macOS 版本、应用版本/build、语言和 SDK 版本。`system_profile` 每次开启采集时报告一次：物理内存字节数、逻辑/活跃处理器数量、Metal 设备数、统一内存、系统运行秒数、调试构建，以及系统支持查询时的 Rosetta 翻译状态。不采集硬件序列号、用户名、设备名称或其他应用的使用情况。

`resource_sample` 启用时立即采一次，此后每 30 秒采样；关闭开关或退出取消任务。指标均来自 Glim 主进程：

| 属性 | 单位与解释 |
| --- | --- |
| `resident_bytes` | 常驻内存字节数 |
| `physical_footprint_bytes` | Mach 统计的物理内存占用；与常驻内存口径不同 |
| `virtual_bytes` | 虚拟地址空间字节数，不能当实际 RAM 占用 |
| `compressed_bytes` | 压缩内存字节数，不能直接与 footprint 相加 |
| `peak_resident_bytes` | 主进程生命周期内的常驻内存高水位 |
| `cpu_total_ns` | 用户态与内核态累计 CPU 纳秒数 |
| `cpu_percent_x100` | 相邻有效采样的 CPU 时间增量/墙钟增量，百分比乘 100；多核可超过 10000，首样本不提供区间值 |
| `metal_allocated_bytes` | Metal 设备对象公开的资源分配量，可能包括共享内存；可用性由 `gpu_counter_available` 表示 |
| `thermal_state` / `low_power_enabled` | 当前热状态、系统支持查询时的低电量模式 |
| `open_tabs` / `workspace_windows` | 当前所有工作区的标签和窗口数量 |
| `workspace_active` / `file_extension` / `reader_kind` | 当前是否有活动工作区，以及当时活动格式/阅读器 |

`scope=main_process`、`includes_helpers=false`：不包含 WebKit 服务、渲染助手或转换子进程的独立内存。`gpu_counter_scope=metal_device_allocations`、`gpu_total_vram_available=false`：Metal 数值不是整机显存、独占显存、完整 GPU 驻留量或 GPU 使用率；API 返回零也不能证明没有 GPU 资源。不能将它与 RAM 相加。资源样本关联活动格式，但其他标签和缓存也占资源，不能宣称是该格式独自消耗的内存。缺失指标用可用性字段区分，不伪造零。

### 滚动与快捷键

`reader_scroll` 汇总一次连续滚动，约 700 毫秒无输入结束，最长连续段约 10 秒；记录输入事件数、持续毫秒和横纵位移。GPUI 记录 points、lines×100、正负方向事件数；原生记录 delta×100 与明确的 `delta_unit`。这是滚轮/触控板输入，不能等同于内容实际移动、滚动深度或读完比例；到达边界仍可能收到输入。GPUI 由已有文档捕获路径收集，原生复用现有 `ReaderContextMenu` 路由，重叠原生路由按事件对象去重；不改变滚动行为。原生段只保证存活期间定时刷新，强退可能丢失尾段。原生页面的方向仅保留横纵绝对位移，GPUI 另有正负方向计数。两套捕获能力不同，不能把原始位移数值直接混算。

`shortcut_used` 收集 GPUI 已解析出的静态命令名、修饰键、固定白名单命令键标记及活动格式，覆盖应用操作、书籍翻页、文件树导航，以及编辑器已解析的复制/剪切/粘贴、撤销/重做、查找和光标命令。普通字符输入不上传文本；未知绑定键为 `other_bound_key`。命令键标记用于区分同一操作的 Space/PageDown 等绑定。GPUI 拦截器或原生视图提前消费的键不会进入这个观察器。

`native_shortcut_used` 由已有原生快捷键处理路径收集，含静态阅读器/动作、Command/Control/Option/Shift 和已识别命令的物理 `key_code`；物理键码不代表当前键盘布局产生的字符。覆盖原生复制、全选、缩放、适配、实际大小、预览文本复制、OCR、外部打开和翻页。原生操作的 `input_source` 为 pointer/keyboard/menu/unknown；异步结果和状态观察不推断用户来源。系统自带菜单、Quick Look、WebKit 或 AVPlayerView 内部未经过这些处理路径的快捷键不保证覆盖。

### 格式操作明细

| 阅读器 | 新增明细 |
| --- | --- |
| CSV/Geo 表格 | 上/下行页、上/下列页、单元格详情、行列偏移、分页格式类别、加载结果与耗时 |
| SQLite | 首/末/上/下页、输入跳页、全局/列筛选是否启用、排序方向、表切换、单元格详情、查询超时扩展；打开、列元数据、计数、分页和单元格读取分别计结果与耗时 |
| EPUB/FB2 等书籍 | 翻页/章节、目录开关、字号增减、字体族、行距、页宽、纸张样式、书签、链接 |
| XMind | 工作表选择、节点选择、节点折叠、全部折叠/展开、视图重置、缩放按钮、复制 |
| OPML | 全部展开/折叠、单节点折叠 |
| 数据树 | 节点折叠、完整值查看、解析加载结果与耗时 |
| Markdown | 本地/网页/邮件链接类别、待办勾选、预览和工具栏操作；不采集 URL 或锚点文本 |
| 分页文本/十六进制 | 前后页、扩展当前页、原始字节/报告模式、复制页、加载结果与耗时 |
| 原生图片 | 复制图像/选区、复制完成/失败、OCR、OCR 结果数与耗时、缩放按钮/手势结束值、适配/原始大小、图片分页、菜单打开 |
| Word/HTML | 加载完成/失败、阅读模式、缩放、链接、复制与菜单操作 |
| 原生表格 | 工作表切换、加载更多工作表、分别记录行页/列页、复制与失败 |
| PDF/演示/字体 | 缩放、适配、布局、演示进入/退出、翻页、外部打开、字体切换 |
| 媒体 | 播放/暂停调用、上下项目、播放失败、观察到的播放/等待/暂停状态、静音状态、合并后的音量值、约每 30 秒的播放位置与已知总时长 |
| 工作区/文件树 | 阅读全屏实际变化、带格式上下文的工具栏调用、右键菜单动作（新建、播放目录/随机播放、打开、Finder 定位、复制相对/绝对路径、废纸篓、移除目录）；仅动作类别，不上传路径 |

`reader_feature` 为阅读器操作尝试，不能统一当作完成；部分操作按阅读器类型归类，未附精确后缀时不要猜测。例如原生 Word 操作可能合并 doc/docx，书籍操作可能合并 epub/fb2；精确格式覆盖人数仍以 `file_open` 为准。原生 `semantic=invocation/outcome/observation` 区分调用、结果和状态观察。OCR 完成附观察结果数量和耗时，不上传识别文字；没有找到文本可以是成功结果。复制未找到可复制文本以静态错误码 2 表示。媒体播放位置与预期相差超过两秒时记 `playhead_jump_observed`，这是启发式观察，缓冲或系统时序也可能触发，不能当精确的用户拖动次数。音量变化合并 400 毫秒内连续更新，不逐帧发事件。

关闭遥测也会停止原生收集，并轮换内存聚合代次；重新开启不会把之前的滚动或播放位置片段补发。所有数据沿用有界队列、去重及丢失计数规则，不能保证强退、断网或极高频操作下逐条送达。API 支持与操作分发的静态接入已完成；实际交互覆盖需在 macOS 手动验证。

### 明细导出

```sh
python3 scripts/telemetry-detail-report.py events.json --output-dir report
```

生成 `timeline.csv`（逐条事件及完整安全属性）、`actions.csv`（事件/格式/阅读器/动作/来源/结果分组）、`shortcuts.csv`（命令与组合键排行）、`resources.csv`（活动格式下主进程指标的样本数、P50/P95/最大值）。支持与格式榜相同的 JSON/JSONL/CSV 输入；相同会话与序号的导出重复行只算一次。时间线保留导出顺序，可按会话与事件序号查看链路；不是可靠的全局因果排序。先在导出中筛选版本与时间范围，再比较报表。安装数缺失时不会伪造人数。

## 命令行过滤与有效使用口径

两个报表脚本支持 ClickHouse JSONEachRow/CSV 的 string_props、numeric_props、os_version、app_version 列，以及 .jsonl.gz 流式读取。用 --app-id 选择生产应用，避免混入其他产品和 DEBUG；用 --exclude-installations-file 读取本地 UTF-8 安装 ID 清单（每行一个，允许 # 注释），也可重复传 --exclude-installation-id。个人 ID 清单放在仓库之外；缺少身份的事件保持未归属。

格式报表增加成功打开安装数、在导出范围内跨 UTC+8 自然日成功打开的安装数，以及源码回退次数。跨日观察不等于 cohort 留存率。详细报表新增 activity.csv，按安装与 UTC+8 日期统计打开次数、成功次数、有打开的会话数和文档前台片段秒数；resource-peaks.csv 保留每个安装各指标峰值对应的时间、版本、格式和窗口/标签数。Aptabase 会话时长含后台驻留，总事件量含大量资源采样，不用它们替代有效使用；前台片段仍包含空闲，不能证明阅读完成。

XMind 解析或工作预算失败但源码分页成功时上报 reader_fallback，固定 reason 区分 container/content_entry/decompression/json/xml/structure/unknown，preview_budget 标识工作预算回退。file_open 成功不保证思维导图渲染成功，需同时查看回退事件。operation_failed 新增 reader_stage 并纳入错误签名，均不上传文档或错误原文。telemetry_health 补齐可用的安装 ID、schema、架构、系统构建和独立序号；error_repeated 聚合使用新序号。历史缺失 ID 无法由本次更新补回。
