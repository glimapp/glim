# 渲染管线与性能方向

本文供性能和阅读器维护者参考，区分当前机制与后续设计方向。普通使用见[使用指南](user-guide.zh-CN.md)；当前能力见[场景专题](topics.zh-CN.md)，不要将本页方向当作已发布功能。

Glim 的统一方向是共享调度机制、格式专属的数据表示和渲染适配器。不要把所有格式转成 Markdown，也不要强制所有格式生成 AST。当前已有格式模块、共享准备任务调度、分页／虚拟滚动和局部缓存；视口级优先级与跨视图内存总账尚未统一。

## 管线

1. 格式探测：结合扩展名、文件头和必要的定点读取识别格式；不为识别格式而读完整文件。探测置信度不足时使用现有完整源后备。
2. 构建中间表示：按格式增量生成可定位、可恢复的索引和内容块；保存源位置、结构版本及资源引用。首屏不等待无关屏外内容完成。
3. 依赖计划：从已发现的内容块生成所需引擎与依赖关系。区分文件格式和块类型，例如 Markdown 同时包含普通文字、图片、Mermaid 和公式。
4. 任务调度：优先处理当前文件的可视区域，再处理相邻区域和屏外预取。IO、解析、引擎初始化、解码与布局分别管理并发和工作内存，不能简单地把全部任务同时启动。
5. 渐进呈现：可读内容准备好即显示，独立显示尚未完成的块。滚动不重新解析全文，屏外区域按需布局和解码。
6. 复用与失效：缓存探测、索引、引擎和渲染结果，明确各自生命周期；以内容／文件身份、引擎版本、样式及尺寸参数失效。切换文件、编辑或改变视口时，取消过时任务并丢弃过时结果。

所有格式保留完整内容的访问路径。限制活动内存、缓冲区和并发，而不是文件总大小；策略继续由 `assets/reader-limits.json` 统一管理。

## 格式专属表示

| 内容 | 合适的数据表示 | 主要工作 |
| --- | --- | --- |
| Markdown | 语法块、源范围、资源／图表依赖 | 增量解析、块虚拟化、嵌入引擎调度 |
| 代码与普通文本 | 文本页、语法树／高亮区间、行索引 | 按视口高亮、编辑与流式保存 |
| 图片／SVG | 尺寸、帧／图层、解码或绘制参数 | 按需解码与缩放，复用字体和图像资源 |
| PDF | 页面索引、页面显示列表 | 可见页优先、相邻页预取 |
| Word 文档 | 段落／列表／样式的阅读投影，原始文档 | 可取消转换、宽度重排与缩放，原始版式后备 |
| XLSX／CSV | 工作表／行列索引、缓存值、样式与合并信息 | 分页、窗口化布局、完整值访问 |
| 音视频 | 媒体轨道、时序／关键帧索引 | 系统解码器、流式读取 |
| 数据库／压缩包 | 模式或目录索引 | 按需查询／解压，控制活动工作集 |

这些表示共享定位、版本、资源依赖和取消语义，保留格式自己的结构。结构化并不等于一次性把全文、所有页面或所有单元格装进内存。

## 已落地的部分

- 格式识别、加载和失败后备集中在 `services/documents` 的静态注册表；普通／分页文本共享阅读投影分类，工作区通过 `reader/construction` 装配视图。
- `DocumentSession` 持有文档身份和修订，刷新结果同时核对文档／编辑／分页版本；监听按路径合并变化，工作空间逐文档串行刷新、当前文档优先，避免同时保留所有已准备内容。文档打开、恢复、刷新及各阅读器的主要准备任务另由共享调度器控制并发，可视区内部调度尚未统一。
- Rust／Swift 原生请求已有带版本的类型契约，非媒体文档不再预先创建播放器；原生控制器仍负责各具体视图的装配和生命周期。

- Markdown 使用固定视口的虚拟块列表；辅助表格、图片和图表扫描先做保守语法预检查，避免无需要时构造 AST。首次正文在插件配置后提交，避免无插件／有插件重复解析。
- 图表进程先分析当前请求批次的类型／子类型，再并发导入实际需要的 ESM 引擎。相同引擎共享模块 Promise；Mermaid 内部图表类型也通过拆分模块按需加载。单个引擎导入失败按块回传，不中止无关类型。
- 所有引擎与拆分模块仍随应用离线内嵌，运行时经私有协议提供。原始文档不会成为可执行脚本；共享 SVG 规范化、资源策略、超时与 IPC 协议保持一致。
- 图表与公式按可视区域自动请求、分批生成并直接替换渲染资源，完成时只更新布局，不重解析全文，也不要求手动切换图表页。阅读器的共享资源缓存受编码／解码及键值预算约束，切走时取消任务并释放缓存。图表 PNG 成功结果另在进程内按类型、完整源和栅格边长复用，以共享 IO 缓存预算淘汰。进程结束后不保留该缓存；错误不入缓存。字体使用内存映射，避免为每个字形反复读取完整字体文件。
- 文本、表格、书籍、数据库等保留分页或磁盘索引；`ReaderSurface` 使各模块管理激活、窗口绑定与刷新，`EditSession` 在文档与文本视图间共享编辑状态。
- `services/work/scheduler` 与 `app/reader_jobs` 对文档、投影、解码、原生准备和图表批次实行进程级异步准入。队列取消移除等待项，运行任务直到真正结束才释放配额；交互／后台队列交替推进。GIF 仍保留有界提前解码，不以动画生命周期占用配额。`reader_job` 分别记录排队与执行耗时。

## 尚未统一的部分

- 将准备任务的共享并发预算继续扩展为视口级优先级、字节资源预留和跨视图缓存回收；SDK 内部的解析／渲染目前仍由系统框架调度。
- Markdown 正文的增量索引与块级解析复用；当前必要的全文解析仍在后台执行。
- 可跨进程复用且有容量回收、版本失效与隐私清理规则的持久缓存。
- 统一性能事件：格式识别耗时、首个可读内容、首屏完整可读、输入／滚动长任务、活动内存峰值与缓存命中率。冷启动和热缓存分别记录；引擎计算、字体转换与界面绘制分别计时。

推进顺序先消除重复工作和资源反复读取，再统一调度和性能观测，最后逐个阅读器迁移。评估以可读首屏和交互延迟为主，不以一次性完成全文为唯一目标。
