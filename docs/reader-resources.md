# Reader resources and rendering

**English** · [简体中文](reader-resources.zh-CN.md) · [Architecture](architecture.md)

Glim combines format-specific data representations with shared admission and resource ownership. Text uses pages and syntax ranges, databases use query windows, workbooks use disk indexes, books use chapters, images use bounded previews, and native documents retain system controllers. Scenarios compose these readers; they do not require a universal AST or conversion to Markdown.

## Resource ownership

`glim-core::resources` implements a UI/I/O-free resource pool. `glim-services::resources::pool()` owns the process-wide instance. Resource leases share a charge across clones and release it when the final owner drops. Resizing updates the existing charge. Counters are constant-time snapshots, not heap measurements.

| Class | Integrated owners | Release/reconstruction |
| --- | --- | --- |
| State | Edit-session text/baseline; OPML/XMind payload and graph expansion-index estimates; book metadata and embedded resources; native request/index metadata | Session lifetime; never evicted as cache |
| Working | CSV/JSON/graph projections and input snapshots, current SQLite grids, paged text/row indexes, minimap geometry, book chapter HTML/anchors and prepared PNGs; static preview/book/inline image/GIF displayed and lookahead pixels; GIF canvas, restore and row buffers; native image rasters shared with copy/OCR and pending clipboard payloads | Canceled work drops its buffers; displayed images defer atlas removal until the window is available |
| Cache | Service diagram PNG reuse and view diagram images/errors | Shared budget; background entries first, then least recently accessed entries within each retention class |

`CachedResource` keeps a key that can become empty. A reader treats an empty entry as a miss and reconstructs it from its original content. `ResourceValue` pins a cache value while a caller owns it; diagram elements retain that pin during rendering. Reclamation runs outside the pool lock and skips busy or pinned entries. The current shared cache target is defined only in `assets/reader-limits.json`; existing local encoded/decoded/key budgets still apply. Allocation triggers reclamation, and explicitly calling `trim` can reclaim newly unpinned entries. Pinned values and newly published results may temporarily exceed the target; a new result stays resident through its initial reclamation pass so cache pressure cannot discard it before publication.

`reserve_working(minimum, desired)` atomically reserves against the shared working target, including existing tracked working owners. A producer receives a smaller grant when capacity is scarce; a request below its minimum returns typed, retryable resource pressure without waiting on a worker. Reservations can shrink but cannot grow without new admission. Text/hex pages reserve before allocating input, display text and line ranges, adapt the byte window, and retain their reservation through publication and display. The prepared page owns its row index and widest-row selection, so view construction does not scan the page. Hiding a read-only page drops both buffers and reservation; failed replacement retains the old readable page. An explicit Retry action reloads the current page. Editable pages transfer their baseline/index accounting to protected state. All source bytes remain reachable by successive page offsets, including UTF-8 characters spanning a window boundary.

`TextRowsBuilder` admits cells, row vectors and outer-vector reallocation peaks before allocating; the immutable `TextRows` result retains that reservation through the UI handoff. CSV/TSV, geographic coordinate pages and SQLite grids share this buffer. CSV parsing separately reserves a conservative envelope for the pinned parser's current record, byte/string headers and input buffer, growing it atomically before further input. CSV and geographic pages can publish a completed row prefix under pressure and resume at the next row; a first row that cannot fit returns an error, leaving complete source access available. SQLite uses fixed page offsets and therefore fails the whole request instead of publishing a shortened page that would skip rows. Its lossy text conversion has a separate bounded scratch reservation; SQLite's engine/cache and geographic XML parser scratch are not yet fully admitted. Table retry controls reuse their existing reload paths.

CSV/geographic and JSON source projections share an admitted `TextSnapshot`: its allocation is reserved before copying borrowed Rope chunks, with no intermediate `SharedString` or second worker copy. An unchanged source reuses the existing owner without another grant. A failed grant leaves the editor intact and allows returning to Source. The snapshot's reservation follows all worker/view owners.

JSON/JSONC/JSON5/JSONL output nodes and graph intermediate nodes use `structured::TreeBuilder`. Node strings, node slots and child-index growth are admitted before allocation, including both allocations during vector replacement; pressure fails the preparation atomically. Construction reuses a growing admitted window and shrinks it to retained capacity at publication, avoiding a shared-pool lock per node. Immutable results retain admission until their last owner drops. The JSON view separately reserves visible-row and traversal arrays before publishing nodes; folding reuses those arrays. Expansion state uses one admitted byte per node and remains charged to the working pool while hidden. Hiding releases nodes and traversal/display arrays while preserving fold/scroll state and the shared input for reconstruction. The adapter exposes retry for preparation/publication errors. JSONC normalization also reserves its copy and checks cancellation in bounded byte intervals; JSONL checks between records and node conversion checks between nodes. Whole parser calls check before/after and remain non-preemptible. Parser `Value` trees, JSON5 parser internals and temporary formatting are not yet fully admitted.

Structured graph conversion reserves traversal storage and the complete final map before allocation. Output strings and index vectors use exact capacities, including full grouped notes, and avoid temporary field arrays or formatted-string copies. The admitted input tree remains owned while output is built; `PreparedGraph` retains the final reservation through worker/view handoff without a second state charge. Pressure or cancellation drops incomplete output and leaves source access intact. XMind parsing, graph layout and parser internals still require separate admission.

Other producers still use unrestricted `track`/`resize`; their bytes reduce reservation availability but can themselves exceed the working target. Converting those paths to admission and adding pressure reclamation of reconstructible active resources remain necessary. This is accounting for integrated owners, not a hard process-memory ceiling. Text capacity/undo history, all retained projections, book HTML parse trees, GPUI asset/atlas caches, ImageIO, WebKit, Quick Look, parser internals and helper-process allocations are not fully represented. Diagram decoded bytes are an estimate. Do not add these counters to OS footprint or Metal counters: they overlap and have different scopes. `resource_sample` includes state, working, cache, cache target and eviction counters under existing telemetry consent.

CSV/JSON projections cancel work and release derived rows/nodes when switching to source or hiding a tab, retaining reconstruction input and necessary query/fold state. Activation rebuilds only the selected projection; the editor session remains independent. Closing a structured graph releases its entity; explicitly reopening it prepares a fresh graph.

Hiding SQLite cancels page, count, detail and snapshot-refresh tasks and releases grid cells. Its private disk snapshot, filter/sort/page, scroll position and open read-only detail remain owned by the reader. Activation reconstructs the current page and restarts only unfinished counts; file refreshes received while hidden wait until activation. A failed refresh during restoration reconstructs the grid from the retained snapshot and reports the error. Queued filter changes still update the retained query after hiding. Open details use editor-state ownership and suspend/reconstruct their optional minimap geometry with reader activation; cancelled detail requests are not automatically replayed.

Hiding a book cancels chapter preparation and releases its HTML view, anchors and image entities while retaining the book metadata, preferences, chapter and position. A nonempty text selection pins the HTML view and encoded chapter images so returning does not lose the selection; decoded images are still released. Restoration does not save default preferences; interrupted initial loading rereads saved preferences. Reading-position snapshots enter a shared pending slot before presentation events are delivered; shutdown sees and drains that slot. Writes coalesce and have an independent lifetime. The borrowed catalog and background jobs retain the original book resource lease; chapter presentation retains the text/anchor lease. A book's source fallback retains the same paged entity and source handle, releasing only reconstructible text/row indexes. Other read-only pages follow the same lifecycle; editable pages keep their edit session and save baseline.

`media::PreparedImage` is shared by static preview pages and book images. Encoded PNGs retain their existing accounting; static, book and inline PNG decoding now passes through `services::media::raster`. It reads only the fixed PNG dimension header before reserving space for the source pixel representation, RGBA conversion and configured decoder workspace. The resulting `RasterFrame` owns the pixels and the remaining working reservation. BGRA conversion and GPUI handoff move this ownership without copying or recounting the image. Decode jobs use the existing scheduler and draw pixels directly without GPUI's implicit image asset cache. Hiding, changing pages or disposing the owner cancels work and defers window-atlas cleanup while retaining the reservation. Static preview pages retain encoded PNGs for reconstruction and copying; leaving a book chapter releases its encoded images and rereads the chapter when needed. Standalone previews expose retry after failed decoding; inline images retry when reactivated or explicitly refreshed.

GIF compositing admits canvas/restore storage and the RGBA converter's retained indexed-row allocation before creating the canvases. Resolution selection leaves room for source rows, two prefetch batches and the displayed frame; each output frame and source row is admitted separately. A smaller grant lowers preview resolution without rejecting original source dimensions. Direct nearest sampling writes only the result buffer, replacing the image library path that creates a full-width floating-point intermediate. Admission failure retains a pending frame header, so retry cannot skip that frame; EOF needs no new pixel allocation. Completed prefetch prefixes can still be displayed under pressure. Standalone animation errors offer retry and keep the last readable frame until retry begins. Dropping a decoder releases its working state while displayed/prefetched frames retain their own reservations.

Encoded preview production, SVG thumbnail intermediates, GIF metadata/LZW internals and native helper allocations are not yet fully admitted. These remain separate from the pixel/row ownership above; integrated raster admission does not establish a process-memory ceiling.

Native prepared results retain disk indexes, converted files and their cleanup ownership. Accounting includes resident configuration/metadata, not disk file sizes. Hiding a tab cancels unfinished preparation while established system controllers retain navigation state. Menu occlusion only hides previews. `native/ReaderResources.swift` shares immutable raster owners across ImageIO result publication, display, Live Text, OCR and copying. Their leases use synchronized numeric handles into the Rust resource pool, independent of telemetry consent. The charge uses actual row stride times height and survives cancellation while a running consumer still owns the pixels. Embedded Office image extraction and delivered PDF/Word OCR snapshots use the same owner; copy-result bytes stay charged until clipboard publication finishes. Framework-internal allocations, encoding intermediates, clipboard-server storage and separate helper processes remain outside this accounting. Shared byte admission is still pending.

## Visible work and cancellation

The shared scheduler has document, projection, decode, native and diagram lanes. FIFO queues use a weighted viewport, interactive, viewport, background cycle, skipping empty queues. Admission waits asynchronously before occupying a worker. A permit stays with the actual work until it exits, including after the UI cancels its task. Running SDK/parser calls are not preempted. Do not hold a permit while synchronously waiting for another permit in a dependency cycle.

Markdown's virtualized image subtree records image requests during layout/paint. After each frame, images absent from that subtree deactivate: still-image requests and GIF downloads/playback cancel, decoded frames release, and returning images reconstruct. GIF constructors do not fetch offscreen URLs; downloaded temporary files can be reused while their reader exists. A GIF restarts when reactivated, including finite animations. Toolkit overscan/layout can request nearby images; this is render demand, not exact pixel visibility. Nested alert images and embedded browser/system viewers retain their own loading paths.

Diagram/formula nodes enqueue bounded viewport batches. Updating render resources invalidates layout without reparsing the full document. Service PNG reuse keys include diagram kind, complete source and raster edge; a persistent result cache backs the process memory cache. Cache eviction does not discard original source. Offline engines remain bundled and load required modules on demand; failures are isolated per result.

## Large-file paths

UTF-8 editing uses pages, bounded streaming copies and atomic saving. XLSX/XLSM builds a disk SQLite cell index; presentation pages preserve cached values, styles and merges without recalculating formulas or executing macros. Books use chapters and on-demand members, with full text/byte member fallbacks. CSV/SQLite cells and geographic coordinates use windows. Archives stream payloads; compressed streams reconstruct their decoder when needed. GIF uses bounded compositing and preview batches; raster images use scaled previews rather than original-resolution tiles. Remote images stream to temporary files. HTML streams through a local-resource worker while WebKit owns DOM/script allocation. Oversized structural projections retain complete source paging.

Source size is not an admission limit. The [generated policy inventory](reader-limits.md) describes working buffers, paging and fallback effects. Library/platform constraints remain: ZIP central-directory allocation, SQLite expression evaluation, native conversion and some indexes can require preparation before the first readable view. Changing numeric policy requires `python3 scripts/generate-reader-limits.py --docs`.

## Parser measurement

Run `cargo bench -p glim-app --bench markdown_edit --locked` on macOS. The harness emits JSON to stdout; save measurements outside the repository with machine, toolchain and commit information. It uses the production TextView parse/update functions, comparing the full-parse baseline with block reuse in the same optimized binary and alternating execution order. Timed work includes baseline cloning, edit detection, parsing, source-span rebasing and result construction; request-string preparation and semantic comparison occur outside the interval. Results must match full parsing before a sample is reported.

Fixtures contain 100, 1,000 and 5,000 paragraphs with Chinese, inline code and links. Head/middle/tail insertions and deletions repeat four times each. Smaller cases exercise lists, tables, fences, reference definitions, appends, indentation, blockquotes, Setext headings, CRLF and HTML boundaries. Output reports initial parse time, each update time, bytes sent to the parser (including old-fragment verification and rejected reuse attempts) and reused block counts. Whole-document references and structural changes intentionally use the baseline path. Reused blocks measure AST reuse, not image/diagram cache hits.

This benchmark measures parser wall time, not first readable pixels, scrolling, typing latency, peak process memory or preview preparation. No UI window is opened. Remaining copies and block cloning scale with document size; large individual blocks and layout remeasurement need separate measurement. The test-support measurement entry point is excluded from ordinary application builds.

## Raster measurement

Run `cargo bench -p glim-services --bench raster_memory --locked` on macOS. It measures GIF setup/frame decoding at 1 MiB, 8 MiB and 512 MiB shared working targets, retaining the same two-batch-plus-display window used by the UI. Wide and ordinary fixtures exercise adaptive raster sizing, disposal, frame ownership after decoder release and complete cleanup. PNG fixtures measure admitted decoding and ownership through BGRA handoff. Fixture generation and pixel/ownership comparisons occur outside timed intervals. The JSON records retained bytes after calls, not transient peak allocation, process RSS or GPU storage. Encoded fixture buffers and decoder metadata are outside this counter; do not interpret it as complete resource coverage. Save results and machine/toolchain/commit information outside the repository.

## Structured-tree measurement

Run `cargo bench -p glim-services --bench structured_tree --locked`. The benchmark alternates the frozen pre-admission parser/projection baseline and current production preparation in the same optimized build, comparing every node's key, full value, summary, kind and child order outside the timed intervals. Fixtures cover 100/1,000/10,000 records, Unicode, duplicate keys, long values, JSONC, JSON5 and JSONL. It measures snapshot copying/matching and parser/projection duration, and verifies pressure denial, retry, cancellation, worker input lifetime and complete release. Retained counters cover snapshots and nodes only; parser internals, view layout, first paint, interaction latency and process peak memory require separate measurements. Keep reports with environment and source provenance outside the repository.

## Source interaction measurement

The same measurement build can observe normal workspace startup: launch the app with `GLIM_MEASURE_STARTUP=1` and read the `workspace-startup` JSON line on stdout. `to_first_frame_submission_ms` measures application entry through the first GPUI frame submission, including ordinary preferences and workspace restoration scheduling. It excludes process loading before application entry and display scanout; it does not imply that all directories or readers have finished loading. Existing user state is used unchanged. The observer stops after the first submitted frame or 30 seconds, and is excluded from ordinary builds.

The opt-in `reader-measurements` feature forwards GPUI's existing profiler; ordinary builds omit the entry point. Build each revision with native `cargo build -p glim-app --release --features reader-measurements --locked`, preserve its binary, then run `python3 scripts/measure-source-reader.py --binary /path/to/candidate --baseline-binary /path/to/baseline --output /outside/repository/source-reader.json`. The runner generates deterministic plain-text fixtures with Chinese text, defaults to 1,000/10,000/50,000 lines and three repetitions, and alternates variant order. Reports retain binary/fixture hashes, machine information, raw samples, medians and p95. Keep build toolchain and source provenance alongside the report. OS file caches are uncontrolled, so these are not cold-disk opens.

The entry point creates an isolated real GPUI window using the production document job, `Reader`, editor and minimap. It does not initialize workspaces, session restoration, autosave or telemetry uploading. Opening starts at document-job submission and records queue plus read time, construction, and the first readable viewport after the production source subtree paints. The extra validation-snapshot copy is reported separately. A frame requires valid text bounds and visible rows, with its content paint matched to GPUI Draw/Present events. Plain source lays out its visible lines synchronously, so first content and first viewport share one sample; asynchronous previews need their own readiness predicate.

Input uses GPUI keystroke dispatch and simulated text input, alternating insertion/backspace at the beginning, middle and end. Exact content and dirty state are checked outside timing. Scrolling dispatches GPUI wheel events and requires viewport movement. Samples distinguish synchronous dispatch time, draw duration and event-to-matching-frame submission. Polling only discovers frames; timestamps come from actual paint/submission events. This excludes physical input latency, GPU completion, display scanout, workspace saving, preview/native readers, cache-hit rates and process peak memory. Fixture contents are checked after each run; scripted edits are never saved.

Edit sessions compare the borrowed Rope with the saved baseline and read its byte length directly for accounting. Change notifications and save acknowledgements no longer materialize full strings for these operations. Different lengths immediately establish a change; equal lengths still compare content chunk by chunk. Source minimaps retain a shared Rope clone instead of a string copy. Updates compare common prefixes/suffixes, skip shared chunk bytes and recompute only affected rows. Unshared chunks still require byte comparisons; the outer block index is rebuilt on changes, so update work is not strictly constant-time. Initial construction and complete replacement scan text chunks sequentially.

Row shapes use immutable blocks of up to 256 rows, a storage invariant rather than a document limit. Outer indexes, blocks and row buffers reserve working bytes before allocation; old painted frames retain their own ownership while untouched blocks are shared. Hiding the reader drops geometry and activation reconstructs it. Failed admission releases optional shapes while keeping current row navigation and the editor intact; a later edit or reactivation retries construction. Editor text and undo ownership remain separate from geometry accounting.

Run `cargo bench -p glim-app --bench minimap_edit --locked` to compare production geometry against the previous full-string-copy/full-geometry algorithm. Fixtures cover 1,000/10,000/50,000 Chinese-text lines, head/middle/tail text and newline insertion/removal, with twelve repetitions and alternating execution order. Initial construction is timed separately; update timing includes allocation while a previous painted snapshot is pinned. Every resulting row is compared outside timing, and JSON records recomputed rows and retained working bytes with both frames. This measures computation and retained admitted storage, not transient process peaks, UI frames or file I/O. Save reports and source/toolchain information outside the repository; use the real-window runner above for input and first-viewport comparisons.

## Diagram caches and hit rates

`services/markdown_preview/cache::ImageCache` owns prepared PNG reuse independently, accepting the shared resource pool and local cache budget. Production access retains a process-wide mutex. Keys include engine kind, full source and raster edge. After shared reclamation, the next lookup removes expired entries and the normal preparation path reconstructs them. Live display consumers pin their resources until release.

`reader/diagrams` also shares successful display previews across tabs within the process, keyed by engine kind and full source. A resident hit reuses the same image object directly, bypassing the diagram job queue and engine preparation when a tab reopens, switches back or reparses unchanged blocks. Closing or hiding a tab cancels its pending work without clearing completed shared previews. Errors remain local to that view so reopening or refreshing can retry. The existing encoded, estimated decoded and key budgets bound the shared preview cache, and resource-pool reclamation can evict unpinned entries. These memory objects do not survive application restarts.

`services/markdown_preview/disk_cache` saves successful PNGs, dimensions and formula baselines to `~/Library/Caches/Glim/Diagrams`. SHA-256 keys include engine kind, complete source, raster edge, bundled engine/rasterizer build inputs, dependency/policy versions, macOS build, architecture and font path/size/modification stamps. Changing these inputs causes a miss; older versions remain eligible for capacity eviction. Filenames and records contain hashes rather than source text or document paths, but PNGs retain rendered document content. The directory is created with owner-only permissions and atomic temporary files with owner-only file permissions. Remove the directory to clear all stored results safely; macOS may also reclaim it.

Disk reads and writes stay in cancellable background diagram jobs, outside UI and memory-cache locks. A hit verifies key, dimensions and payload integrity before publishing into the memory cache and avoids launching WebKit. Corrupt entries are removed and regenerated; unavailable or full storage never prevents ordinary rendering. The shared policy's `diagram.disk_cache_bytes` bounds stored file bytes, with temporary writes and concurrent processes able to exceed the target briefly. Last-use timestamps drive eviction; cleanup retains a bounded candidate window and rescans when needed. Only successful results persist. Existing cache-hit counters describe the two memory layers and do not measure disk hits or avoided engine work.

`CacheActivity` counts hits, misses and pending requests at consumer lookup boundaries. Service image and view preview caches have separate counters; a previously absent key counts as a miss. Publication, pinning, residency peeks and trimming are excluded. A pending preview has already queued preparation and is excluded from the hit-rate denominator; reusing a cached error is still a resident hit. A resident service hit may exceed the current batch's remaining allowance, so it is not a count of rendering avoided.

Local counters accumulate within the process and retain neither text nor cache keys. The existing consent-controlled `resource_sample` exports interval deltas only. Enabling or restarting sampling establishes a new baseline without backfilling disabled periods. Calculate each layer's hit rate as `hits / (hits + misses)`; leave the rate absent when no lookups occurred. The two layers have different denominators and must not be combined into one rate.

Run `cargo bench -p glim-services --bench diagram_cache --locked` to compare a prepared PNG miss plus publication with resident lookup, checking key isolation, pinning, shared pressure reclamation, reconstruction and full release. PNG encoding and content comparisons are outside timing. This excludes diagram engines, WebViews, UI frames and process peak memory. Keep raw samples and environment/source provenance outside the repository.
